## 1. แก้ก่อนอย่างอื่น: ปริศนา 42 vs 39 — ไขแล้ว

โน้ต 05 หัวข้อ 2.2 เคยหมายเหตุไว้ว่า 36 + 3 = 39 ไม่ใช่ 42 และเดาว่าเป็นความ
คลาดเคลื่อนของต้นฉบับ — **ไม่ใช่** ตัวเลข 42 ถูกต้อง เพราะมีก้อนที่สามที่โน้ต 03
ไม่ได้นับรวมใน "36":

```python
# tron1-rl-isaaclab/rsl_rl/rsl_rl/algorithm/ppo.py:138
torch.cat((encoder_out, obs, commands), dim=-1)
#          ────3────    ─36─  ───3────      = 42  ← actor input

# ppo.py:134
torch.cat((critic_obs, commands), dim=-1)
#          ───227────   ───3────            = 230 ← critic input
```

`commands` คือ `velocity_commands` = เป้าหมายความเร็ว $(v_x, v_y, \omega_z)$ ที่
ผู้ใช้สั่ง — 3 ค่า มันเป็น **observation group แยก** ชื่อ `"commands"` ใน
`ObservationsCfg` ([limx_base_env_cfg.py:227](../tron1-rl-isaaclab/exts/bipedal_locomotion/bipedal_locomotion/tasks/locomotion/cfg/SF/limx_base_env_cfg.py#L227))
ไม่ได้อยู่ใน group `"policy"` ที่มี 36 ค่า โน้ต 03 นับแค่ group `policy` จึงได้ 36

| ก้อน | มิติ | มาจาก | ใครเห็น |
| --- | --- | --- | --- |
| latent (encoder output) | 3 | `obsHistory` 360 → MLP → 3 | actor |
| `policy` obs | 36 | IMU + joint encoder + gait clock | actor |
| `commands` | 3 | เป้าหมายความเร็วที่สั่ง | **ทั้ง actor และ critic** |
| `critic` obs (privileged) | 227 | ซิมรู้ทุกอย่าง | critic |

$$\text{actor input} = 3 + 36 + 3 = 42 \qquad \text{critic input} = 227 + 3 = 230$$

โน้ต 05 หัวข้อ 2.2 และ 4.3 แก้ตามนี้แล้ว (ลบหมายเหตุ "ความคลาดเคลื่อน" ออก)

## 3. วิธีอ่าน notation ให้ได้ความหมายเชิงสัญชาตญาณ

สัญลักษณ์ RL ดูน่ากลัวเพราะ **ซ้อนกันหลายชั้นในตัวเดียว** — $\pi_\theta(a_t \mid s_t)$
มีข้อมูล 5 อย่างอัดอยู่ พออ่านแยกชั้นได้ มันจะกลายเป็นประโยคธรรมดา

### กฎการอ่าน 8 ข้อ — ท่องให้ได้ก่อน

| # | เห็นอะไร | อ่านว่า | ตัวอย่าง |
| --- | --- | --- | --- |
| 1 | **ตัวห้อย $t$** | "ณ step ที่ $t$" — ไม่ใช่ตัวแปรคนละตัว แค่ตัวเดิมคนละเวลา | $s_t, a_t, r_t$ = state/action/reward ที่ step $t$ |
| 2 | **ตัวห้อยกรีก $\theta, \phi$** | "ขึ้นกับ weight ชุดนี้" = **สิ่งนี้เป็น neural network ที่ฝึกได้** | $\pi_\theta$ = actor ที่มี weight $\theta$ · $V_\phi$ = critic ที่มี weight $\phi$ |
| 3 | **วงเล็บ** $f(x)$ | "ป้อน $x$ เข้าไป ได้ค่าออกมา" — ฟังก์ชัน | $V(s)$ = ป้อน state ได้ค่าประเมิน |
| 4 | **ขีดตั้ง** $\mid$ | "**เมื่อรู้ว่า**" — สิ่งขวาขีดคือเงื่อนไข สิ่งซ้ายคือสิ่งที่ถาม | $\pi(a \mid s)$ = ความหนาแน่นของ $a$ *เมื่อรู้ว่า* อยู่ที่ $s$ |
| 5 | **$\mathbb{E}[\cdot]$** | "ค่าเฉลี่ยถ้าทำซ้ำหลาย ๆ รอบ" → **ในโค้ดคือ `.mean()` บน batch** | $\mathbb{E}[\rho A]$ ↔ `(ratio * adv).mean()` |
| 6 | **$\sim$** | "**สุ่มจาก**" — ไม่ใช่ "ประมาณเท่ากับ" | $a \sim \pi(\cdot \mid s)$ = $a$ ถูกสุ่มจาก distribution $\pi$ · $\varepsilon \sim \mathcal N(0,1)$ |
| 7 | **$\nabla_\theta$** | "ความชันเทียบกับ $\theta$" — เวกเตอร์ยาวเท่าจำนวน weight บอกทิศที่ loss เพิ่ม | $\nabla_\theta L$ ↔ `loss.backward()` แล้วดู `.grad` |
| 8 | **ตัวยก** $X^{\text{ชื่อ}}$ | "แบบ/วิธี ชื่อนี้" — ไม่ใช่ยกกำลัง | $A^{GAE}$ = advantage *แบบ* GAE · $L^{CLIP}$ = loss *แบบ* clip |

**ลองแกะ $\pi_\theta(a_t \mid s_t)$ ทีละชั้นด้วยกฎข้างบน:**

```text
π_θ(a_t | s_t)
│ │  │    │
│ │  │    └── กฎ 1: state ที่ step t
│ │  └─────── กฎ 4: "เมื่อรู้ว่า" — เงื่อนไขคือ s_t
│ └────────── กฎ 2: มี weight θ → เป็น neural network (actor)
└──────────── π = policy

อ่านเป็นประโยค: "policy (ที่เป็น network weight θ) บอกว่า ถ้าอยู่ที่ state s_t
                 ความหนาแน่นที่จะเลือก action a_t เป็นเท่าไหร่"
```

### สัญลักษณ์ที่ "หน้าตาคล้าย" แต่คนละความหมาย — จุดสับสนบ่อย

| คู่ที่สับสน | ต่างกันตรงไหน |
| --- | --- |
| $\theta$ vs $\phi$ | สองชุด weight ของสอง network — $\theta$ actor (deploy), $\phi$ critic (ทิ้ง) · gradient ไหลแยกกัน |
| $\pi$ vs $\pi(a\mid s)$ | ตัว network ทั้งอัน vs ตัวเลขเดียวที่คำนวณจากมัน — โน้ต 05 หัวข้อ 2.3 |
| $V(s)$ vs $V_\phi(s)$ | ค่าจริงในทฤษฎี vs ค่าที่ network ประมาณ — ตัวห้อย $\phi$ บอกว่า "นี่คือการเดา ผิดได้" |
| $A_t$ vs $A^{GAE}_t$ | นิยาม (10) $Q - V$ vs วิธีประมาณจริง (11) — ในโค้ดมีแต่ตัวหลัง |
| $R_t$ vs $r_t$ | ผลรวมจนจบ (return) vs step เดียว (reward) — ตัวใหญ่ = ยาว |
| $\mathbb{E}[\cdot]$ vs `mean()` | ค่าคาดหวังทางทฤษฎี (เฉลี่ยจากอนันต์รอบ) vs ค่าเฉลี่ยจาก 12,288 ตัวอย่าง — อย่างหลังคือการประมาณอย่างแรก |
| $\sim$ vs $=$ vs $\approx$ | สุ่มจาก / เท่ากับ / ประมาณ — $a \sim \mathcal N(\mu,\sigma)$ ไม่ได้แปลว่า $a \approx \mu$ |
| $\epsilon$ (clip 0.2) vs $\varepsilon$ (noise) | ตัวอักษรกรีกคนละตัว — epsilon ธรรมดา = ขอบ clip · varepsilon = ตัวสุ่ม |
| $\gamma\lambda$ | ไม่ใช่ตัวแปรใหม่ — คือ $0.99 \times 0.95 = 0.9405$ ตัวถ่วงน้ำหนักของ GAE |

### วิธีอ่านสมการยาว ๆ — ทำสามรอบ

ใช้สมการ (12) เป็นตัวอย่าง:

$$L^{CLIP} = \mathbb{E}\Big[\min\big(\rho_t A_t,\; \text{clip}(\rho_t, 1-\epsilon, 1+\epsilon)\, A_t\big)\Big]$$

| รอบ | ทำอะไร | ผลที่ได้ |
| --- | --- | --- |
| **1. หาโครง** | มองข้ามตัวห้อย/ตัวยกทั้งหมด หา operator หลัก | `E[ min( __ , __ ) ]` — "เฉลี่ยของค่าที่น้อยกว่าระหว่างสองอย่าง" |
| **2. เติมชื่อ** | แทนสัญลักษณ์ด้วยคำจากตาราง | "เฉลี่ยของ min( ratio×advantage , ratio-ที่ถูกตัด×advantage )" |
| **3. ถามว่าทำไม** | แต่ละส่วนป้องกันอะไร | min = เลือกทางที่ให้รางวัลน้อยกว่า = กันไม่ให้ actor โลภเกิน · clip = ขอบ ±20% |

หลังรอบ 3 สมการจะกลายเป็นประโยค: *"ให้รางวัล action ที่ดี แต่ถ้า policy เปลี่ยน
เกิน 20% แล้ว หยุดให้"* — นี่คือความหมายเชิงสัญชาตญาณ และคือสิ่งที่โค้ด
[ppo.py:256-260](../tron1-rl-isaaclab/rsl_rl/rsl_rl/algorithm/ppo.py#L256-L260) ทำจริง

### 3.5.0 policy คืออะไรกันแน่ — นิยามหนึ่งบรรทัด

$$\pi_\theta : \mathcal{S} \longrightarrow \Delta(\mathcal{A})$$

อ่านว่า **"policy คือฟังก์ชันที่รับ state แล้วคืน *การแจกแจง* บน action"**

| สัญลักษณ์ | อ่านว่า |
| --- | --- |
| $\mathcal{S}$ | เซตของ state ทั้งหมดที่เป็นไปได้ |
| $\mathcal{A}$ | เซตของ action ทั้งหมดที่เป็นไปได้ (ของ Tron1 คือ $\mathbb{R}^8$) |
| $\Delta(\mathcal{A})$ | เซตของ**การแจกแจง**บน $\mathcal{A}$ — สมาชิกแต่ละตัวคือระฆังหนึ่งใบ |

**อ่านบรรทัดประกาศชนิดนี้ยังไง**

$$\underbrace{\pi_\theta}_{\text{ชื่อ}} \underbrace{:}_{\text{"มีชนิดเป็น"}} \underbrace{\mathcal{S}}_{\text{รับ}} \underbrace{\longrightarrow}_{\text{"ฟังก์ชันไปยัง"}} \underbrace{\Delta(\mathcal{A})}_{\text{คืน}}$$

บรรทัดนี้**ไม่ได้คำนวณอะไรเลย** — มันแค่ประกาศว่าของชิ้นนี้เป็นอะไร เหมือน type
annotation ในโปรแกรม

**เครื่องหมาย $\longrightarrow$** แปลว่า *"เป็นฟังก์ชันจาก…ไปยัง…"* ซึ่งเป็นการใช้งานคนละแบบ
กับลูกศรอื่นในโน้ตนี้ · ตัวชี้ขาดคือ **มีเครื่องหมาย $:$ นำหน้าหรือเปล่า** — ถ้ามี แปลว่า
กำลังประกาศชนิด ลูกศรตัวนั้นคือลูกศรฟังก์ชัน (เทียบลูกศรทุกแบบได้ที่ E6 §3.5.4)

**เครื่องหมาย $\Delta$ ไม่ใช่ผลต่าง และไม่ใช่เซตว่าง** · $\Delta(\mathcal{A})$ อ่านว่า *"เซตของการ
แจกแจงความน่าจะเป็นทั้งหมดที่เป็นไปได้บน $\mathcal{A}$"* — เป็นเซตจริง แต่สมาชิกของมัน
ไม่ใช่ตัวเลข **สมาชิกแต่ละตัวคือระฆังหนึ่งใบ**

*ทำไมใช้รูปสามเหลี่ยม* — เพราะวาดออกมาแล้วเป็นสามเหลี่ยมจริง ๆ · ลูกเต๋า 3 หน้า
การแจกแจงหนึ่งอันคือ $(p_1,p_2,p_3)$ ที่ $p_i \ge 0$ และ $p_1{+}p_2{+}p_3 = 1$ · วาดจุดพวกนี้
ในปริภูมิ 3 มิติจะได้สามเหลี่ยมที่มีมุมสามมุมคือ $(1,0,0)$, $(0,1,0)$, $(0,0,1)$

| $\mathcal{A}$ มีกี่ทางเลือก | $\Delta(\mathcal{A})$ หน้าตาเป็น |
| --- | --- |
| 2 | เส้นตรง |
| 3 | **สามเหลี่ยม** ← ที่มาของสัญลักษณ์ |
| 4 | ทรงสี่หน้า |
| ต่อเนื่อง (Tron1) | วาดไม่ได้ มิติอนันต์ — แต่ความหมายเดิม |

ศัพท์เทคนิคของรูปนี้คือ **simplex** · $\Delta$ จึงเป็นสัญลักษณ์มาตรฐานของ "เซตของการแจกแจง"

> **ระวังสับสน** — $\Delta$ ตัวใหญ่ = *เซตของการแจกแจง* · $\delta_t$ ตัวเล็ก = *TD error*
> ในสมการ GAE · ตัวอักษรกรีกตัวเดียวกัน คนละขนาด คนละความหมายสิ้นเชิง

**เอาสัญกรณ์นี้ไปอ่านของที่รู้จักอยู่แล้ว**

| ของ | ประกาศชนิด | อ่านว่า |
| --- | --- | --- |
| ยกกำลังสอง | $f : \mathbb{R} \to \mathbb{R}$ | รับจำนวนจริง คืนจำนวนจริง |
| **Actor NN** | $\mu_\theta : \mathbb{R}^{42} \to \mathbb{R}^{8}$ | รับเวกเตอร์ 42 คืนเวกเตอร์ 8 |
| **Critic** | $V_\phi : \mathbb{R}^{230} \to \mathbb{R}$ | รับเวกเตอร์ 230 คืนเลขตัวเดียว |
| **Encoder** | $f_\psi : \mathbb{R}^{360} \to \mathbb{R}^{3}$ | รับ 360 คืน 3 |
| **Policy** | $\pi_\theta : \mathcal{S} \to \Delta(\mathcal{A})$ | รับ state คืน**ระฆังหนึ่งใบ** |

สามแถวกลางคืนตัวเลข · **แถวล่างคืนของที่ไม่ใช่ตัวเลข** — นั่นคือทั้งหมดที่ $\Delta$ ทำหน้าที่บอก

**$\Delta$ หายไปตัวเดียว ความหมายเปลี่ยนทั้งบรรทัด**

$$\mu_\theta : \mathcal{S} \to \mathcal{A} \qquad\text{เทียบกับ}\qquad \pi_\theta : \mathcal{S} \to \Delta(\mathcal{A})$$

ไม่มี $\Delta$ → คืน action ตรง ๆ = deterministic policy = ตอน deploy · มี $\Delta$ → คืน
การแจกแจง ต้องสุ่มอีกขั้น = stochastic policy = ตอนเทรน

> **เกร็ด** — $\Delta(\mathcal{A})$ บรรจุการแจกแจง**ทุกแบบ**ที่คิดออก (สองยอด เบ้ซ้าย ประหลาด
> ยังไงก็ได้) · การเลือกใช้ Gaussian คือการบอกว่า *"จะหยิบจากมุมเล็ก ๆ มุมเดียวของเซตนี้"*
> — ตรงกับที่ §3.5.2 เรียกว่า interface กับ implementation พอดี

**"การแจกแจง *บน* action" กับ "การแจกแจง *ของ* action" ต่างกัน**

ต้นตอของความสับสนคือ **คำว่า "action" ในภาษาไทยกำกวม** — มันเป็นได้ทั้งสองอย่าง:

| "action" หมายถึง | สัญลักษณ์ | คืออะไร |
| --- | --- | --- |
| ท่าที่เป็นไปได้**ทั้งหมด** | $\mathcal{A}$ | **เซต** — รายการทางเลือก นอนนิ่งอยู่เฉย ๆ |
| ท่าที่**สุ่มได้จริง**ในสเต็ปนี้ | $a$ | **ตัวแปรสุ่ม** — เปลี่ยนทุกครั้งที่ทอย |

พอพูดว่า "action" เฉย ๆ จึงเลือกคำเชื่อมไม่ถูก · **พอเปลี่ยนเป็นสัญลักษณ์ ความกำกวม
หายทันที**

*ตัวอย่างที่ 1 — ปาลูกดอก* · กระดาน = ทุกตำแหน่งที่ลูกดอกไปลงได้ ($\mathcal{A}$) ·
ลูกดอกที่ปาไปเมื่อกี้ = ลงตรงไหนก็ไม่รู้ ปาใหม่ก็คนละที่ ($a$)

| ประโยค | ถูกไหม | เพราะ |
| --- | --- | --- |
| "ความน่าจะเป็นกระจายอยู่ **บนกระดาน**" | ✓ | กระดานเป็นพื้นที่ ให้โปรยได้ |
| "การแจกแจง **ของลูกดอกที่ปา**" | ✓ | ลูกดอกลูกนั้นเป็นของที่สุ่ม |
| "การแจกแจง **ของกระดาน**" | ✗ | กระดานไม่ได้สุ่มอะไร มันแขวนอยู่เฉย ๆ |
| "การแจกแจง **บนลูกดอก**" | ✗ | ลูกดอกลูกเดียว ไม่ใช่พื้นที่ให้กระจาย |

*ตัวอย่างที่ 2 — ลูกเต๋า* · $\mathcal{A} = \{1,\dots,6\}$ (เซต) · $a = 4$ ผลการทอยครั้งนี้

| ประโยค | ถูกไหม |
| --- | --- |
| "การแจกแจง**บน** $\{1,\dots,6\}$" | ✓ |
| "การแจกแจง**ของ**ผลการทอย" | ✓ |
| "การแจกแจง**ของ** $\{1,\dots,6\}$" | ✗ เซตไม่ทอยตัวเอง |
| "การแจกแจง**บน**ผลการทอย" | ✗ ผลการทอยเป็นเลขตัวเดียว |

*ตัวอย่างที่ 3 — Tron1* · $\mathcal{A} = \mathbb{R}^8$ ท่าที่เป็นไปได้ทั้งหมด ·
$a = [0.61, -0.37, 0.505, \dots]$ ท่าที่สุ่มได้จริงในสเต็ปนี้

| ประโยค | ถูกไหม |
| --- | --- |
| "$\Delta(\mathcal{A})$ = เซตของการแจกแจง**บน** $\mathbb{R}^8$" | ✓ |
| "$\pi_\theta(\cdot\mid s)$ คือการแจกแจง**ของ** $a$" | ✓ |
| "การแจกแจง**ของ** $\mathbb{R}^8$" | ✗ |

> **การทดสอบข้อเดียวที่ใช้ได้ทุกครั้ง** — ถามว่า *"สิ่งนี้สุ่มได้ไหม"* · สุ่มไม่ได้ (เป็นพื้นที่ /
> รายการทางเลือก) → ใช้ **"บน"** · สุ่มได้ (ทำใหม่ได้ค่าใหม่) → ใช้ **"ของ"** ·
> จำสั้นกว่านั้น: **"บน" ตอบว่า *ที่ไหน* · "ของ" ตอบว่า *ใคร***

ดังนั้นสองประโยคนี้ไม่ได้ขัดกัน แค่มองคนละมุมของเรื่องเดียวกัน — และในบรรทัด
$\pi_\theta : \mathcal{S} \to \Delta(\mathcal{A})$ ตัวอักษรเขียนไว้ชัดแล้วว่าเป็น $\mathcal{A}$ ตัวใหญ่
จึงอ่านว่า **"บน"** อย่างเดียว ไม่มีทางเลือกอื่น

$$\underbrace{\text{"บน } \mathcal{A}\text{"}}_{\text{บรรยาย}\ \textit{ผืนผ้าใบ}} \qquad\qquad \underbrace{\text{"ของ } a\text{"}}_{\text{บรรยาย}\ \textit{สิ่งที่ออกมา}}$$

> ภาษาอังกฤษแยกด้วยคำบุพบทเหมือนกัน — ตำรา RL เขียน *"a distribution **over**
> actions"* ในนิยาม policy เสมอ ส่วน *"the distribution **of** X"* ใช้เมื่อ $X$ เป็นตัวแปรสุ่ม

**จุดสำคัญที่สุด: มันคืน *การแจกแจง* ไม่ได้คืน *action*** — ความสับสนแทบทั้งหมดเรื่อง
สัญกรณ์ของ policy เกิดจากตรงนี้จุดเดียว เพราะมันแปลว่ากว่าจะได้ action ต้องผ่าน
**สองขั้น** ไม่ใช่ขั้นเดียว:

```
       ขั้นที่ 1: ใส่ s เข้าไป              ขั้นที่ 2: เลือกทำอย่างใดอย่างหนึ่ง
                                          ┌── สุ่ม  ────▶ a        (ได้ action)
   π_θ  ──────────────▶  π_θ(·|s)  ───────┤
  policy              ระฆัง 1 ใบ           └── แทนค่า a ──▶ 0.7423  (ได้ตัวเลข)
```

ขั้นที่ 1 คือการเรียกฟังก์ชัน · ขั้นที่ 2 มีสองทางเลือกที่**ไม่เกี่ยวกัน** — และนี่คือเหตุผล
ที่สัญลักษณ์ต้องมีหลายแบบ

| เขียนว่า | ชนิด | หมายถึง | ในโค้ด |
| --- | --- | --- | --- |
| $\pi$ | ฟังก์ชัน | policy ทั่วไป ไม่ระบุว่าของใคร | — |
| $\pi_\theta$ | ฟังก์ชัน | policy **ตัวนี้** ที่มีพารามิเตอร์ $\theta$ | `self.actor_critic` |
| $\pi_\theta(\cdot\mid s)$ | **การแจกแจง** | ระฆัง **1 ใบ** ที่ได้จากการใส่ $s$ | `Normal(mean, std)` |
| $a \sim \pi_\theta(\cdot\mid s)$ | **การกระทำ** | สุ่มจากระฆังใบนั้น | `.sample()` |
| $\pi_\theta(a\mid s)$ | **scalar** | ความหนาแน่นที่จุด $a$ | `.log_prob(a).sum(-1)` |
| $\mu_\theta(s)$ | เวกเตอร์ `(8,)` | ตำแหน่งกลางของระฆัง | `self.actor(obs)` |

**ชนิดเปลี่ยนทุกแถว** — ฟังก์ชัน → การแจกแจง → เวกเตอร์ → เลขตัวเดียว

**policy ของ Tron1 ประกอบด้วยสามชิ้น**

$$\pi_\theta(\cdot\mid s) = \mathcal{N}\Big(\underbrace{\mu_\theta(s)}_{①\ \text{NN } 42\to8},\ \underbrace{\sigma_\theta}_{②\ \texttt{logstd}}\Big) \qquad ③\ \text{รูประฆัง (คนเลือก)}$$

| ชิ้น | คืออะไร | ขนาด | เรียนไหม |
| --- | --- | --- | --- |
| ① NN | ให้ตำแหน่งระฆัง | 187,272 weight | ✓ |
| ② `logstd` | ให้ความกว้าง | 8 ตัว | ✓ |
| ③ สูตร $\mathcal{N}$ | ให้รูปทรง | 0 (เป็นบรรทัดโค้ด) | ✗ ตายตัว |

**ถ้าจำได้สมการเดียว ให้จำสมการนี้** — ทุกหัวข้อย่อยที่เหลือใน §3.5 แตกออกมาจากมัน

**คำว่า "policy" ในชีวิตจริงมีสามความหมาย**

| ใครพูด | หมายถึง | ตรงกับ |
| --- | --- | --- |
| ตำรา RL | ฟังก์ชัน $\mathcal{S} \to \Delta(\mathcal{A})$ | ① + ② + ③ |
| โปรแกรมเมอร์ | NN ที่ deploy ลงหุ่น | ① อย่างเดียว |
| ไฟล์ `policy.onnx` | NN ที่ export แล้ว | ① อย่างเดียว |

ทั้งสามความหมาย**ตรงกันพอดีตอน deploy** เพราะ ② ถูกทิ้งและ ③ ไม่ถูกใช้ เหลือแค่ ① ·
จึงไม่มีใครพูดผิดเวลาเรียก `policy.onnx` ว่า policy · กฎง่าย ๆ คือ **ถ้าประโยคนั้นมีคำว่า
"ความน่าจะเป็น" หรือ "สุ่ม" อยู่ ต้องแยกให้ออก** ถ้าไม่มี เรียก NN ว่า policy ได้ตามสบาย

**Deterministic กับ Stochastic ใช้คนละสัญกรณ์**

| แบบ | สัญกรณ์ | คืนอะไร | ใครใช้ |
| --- | --- | --- | --- |
| **Stochastic** | $a \sim \pi_\theta(\cdot\mid s)$ | การแจกแจง แล้วสุ่ม | Tron1 **ตอนเทรน** · PPO, SAC |
| **Deterministic** | $a = \mu_\theta(s)$ | action ตรง ๆ | Tron1 **ตอน deploy** · DDPG, TD3 |

ต่างกันที่เครื่องหมาย **$\sim$ กับ $=$** จุดเดียว และมันบอกทุกอย่าง

> **ประโยคปิดท้ายที่ควรจำ** — policy ไม่ใช่ *"ตัวเลือก action"* แต่เป็น *"ตัวออกความเห็นว่า
> แต่ละ action น่าเล่นแค่ไหน"* · ส่วนการเลือกจริงเป็นอีกขั้นที่ต่อจากนั้น — ตอนเทรน
> ขั้นที่สองคือ **สุ่ม** ตอน deploy ขั้นที่สองคือ **หยิบจุดกลาง** · policy ตัวเดียวกัน
> แต่ขั้นที่สองคนละแบบ

### 3.5.1 ขีดตั้ง $\mid$ ต่างจากคอมมา อย่างไร

$f(a, s)$ กับ $f(a \mid s)$ **รับ input เท่ากันทั้งคู่ (สองตัว) และคืน scalar เหมือนกัน**
arity ไม่ต่างกันเลย สิ่งที่ต่างคือขีดตั้งประกาศเงื่อนไขเพิ่มหนึ่งข้อที่คอมมาไม่ประกาศ:

$$\int \pi_\theta(a \mid s)\, da = 1 \qquad \text{สำหรับ } s \text{ ทุกค่า}$$

รวมทางฝั่ง**ซ้าย**ของขีดได้ 1 เสมอ · รวมทางฝั่ง**ขวา**ไม่มีความหมาย ($\sum_s \pi(a\mid s) \ne 1$)
ขีดตั้งจึงเป็นตัวบอกว่า **ตัวไหนคือตัวแปรสุ่ม ตัวไหนคือสิ่งที่ตรึงไว้** ถ้าเขียน $\pi(a, s)$
จะแปลว่าเป็น joint distribution — กระจายบนทั้งคู่ ซึ่งผิด เพราะ policy ไม่ได้บอกว่า
state ไหนน่าจะเกิด (นั่นเป็นหน้าที่ของ $P$ ใน MDP — โน้ต 05 หัวข้อ 1.3)

ในวงเล็บนี้มีถึง **สามช่อง คนละชนิด**:

$$\pi_{\underbrace{\theta}_{\text{parameter}}}\big(\ \underbrace{a}_{\text{ตัวแปรสุ่ม}}\ \mid\ \underbrace{s}_{\text{เงื่อนไข}}\ \big)$$

**ในทางโปรแกรมไม่มี operator สำหรับขีดตั้ง** แต่มันตรงกับโครงสร้างโค้ดพอดี:

| ในสูตร | ในโค้ด | ทำไม |
| --- | --- | --- |
| ขวาขีด ($s$) | argument ของ **constructor** `Normal(...)` | ใช้กำหนดรูปร่างของ distribution |
| ซ้ายขีด ($a$) | argument ของ **method** `.log_prob()` | ค่าที่เอาไปถามว่าหนาแน่นเท่าไร |
| ห้อยล่าง ($\theta$) | **`self`** ของ `nn.Module` | ไม่ได้ส่งเข้าไป มันอยู่ใน object |

นี่คือเหตุผลที่ `update_distribution(obs)` กับ `get_actions_log_prob(actions)` เป็น
**คนละ method** — ถ้าขีดตั้งไม่มีความหมาย มันคงเขียนเป็น `log_prob(a, s)` ฟังก์ชันเดียวจบ

### 3.5.2 สามสัญลักษณ์ที่สับสนบ่อยที่สุด · และเครื่องหมาย $=$ ระหว่างการแจกแจง

**ก่อนอื่น — $f$ กับ $f(x)$ ต่างกันยังไง**

ทุกอย่างในหัวข้อนี้ตั้งอยู่บนความต่างข้อเดียว: *ตัวฟังก์ชัน* กับ *ค่าที่ฟังก์ชันคายออกมา*
เป็นคนละสิ่งกัน

| | คืออะไร | ทำอะไรกับมันได้ |
| --- | --- | --- |
| **เครื่องชงกาแฟ** | ตัวเครื่อง 1 เครื่อง | ยกไปวางที่อื่น · ถามว่ากินไฟกี่วัตต์ |
| **กาแฟ 1 แก้วที่มันชง** | ของเหลว 1 แก้ว | ดื่ม · วัดอุณหภูมิ |

ดื่มเครื่องชงไม่ได้ และเสียบปลั๊กแก้วกาแฟไม่ได้ — คณิตศาสตร์เหมือนกันเป๊ะ:

| | เขียนว่า | คืออะไร |
| --- | --- | --- |
| **ตัวเครื่อง** | $f$ | กฎการแปลง — ใส่อะไรเข้าไปได้อะไรออกมา |
| **ของที่ออกมา** | $f(x)$ | ตัวเลขหนึ่งตัว |

ให้ $f =$ "ยกกำลังสอง" · ประโยคที่พูดถึง**ตัวเครื่อง** คือ *"กราฟของ $f$ เป็นพาราโบลา"*
หรือ *"$f$ มีค่าต่ำสุดที่ $x = 0$"* — พูดถึง*ทั้งเส้นกราฟ* · ส่วน $f(3) = 9$ คือ*เลขตัวเดียว*
จุดเดียวบนกราฟ

> **วิธีแยกที่ใช้ได้ทุกครั้ง** — ถามว่า *"ตอบเป็นตัวเลขได้ไหม"* · $f$ ตอบไม่ได้ เพราะมันคือ
> กฎ/กราฟทั้งเส้น · $f(3)$ ตอบได้ คือ 9

**เอามาใช้กับ policy** — ถ้า $\mu = 0.42$ และ $\sigma = 0.5$ ระฆังอันนี้กำหนดความสูงไว้ให้
**ทุกค่าของ $a$ ที่เป็นไปได้** ไม่ใช่แค่ค่าเดียว:

| $a$ | $-1.0$ | $0.0$ | $0.42$ | $0.61$ | $1.5$ | … ทุกค่าบนเส้นจำนวนจริง |
| --- | --- | --- | --- | --- | --- | --- |
| ความสูง | $0.0141$ | $0.5607$ | $0.7979$ | $0.7423$ | $0.0774$ | … |

- **ทั้งตารางรวมกัน** (ที่จริงยาวไม่รู้จบ) $= \pi_\theta(\cdot\mid s)$ — *ตัวเครื่อง*
- **หนึ่งช่องในตาราง** $= \pi_\theta(a\mid s)$ — *ของที่ออกมา*

ในโค้ดก็แยกกันชัดแบบเดียวกัน · `print(dist)` จะได้ `Normal(loc: 0.42, scale: 0.5)`
ไม่ใช่ตัวเลข เพราะมันคือเครื่อง ไม่ใช่กาแฟ:

```python
dist = Normal(0.42, 0.5)     # ← ตัวเครื่อง : ตัวแปร dist เก็บระฆังทั้งอัน
dist.log_prob(0.61)          # ← หนึ่งช่อง  : เลขตัวเดียว
```

> **ศัพท์ที่โน้ตนี้ใช้** — เรียก $\pi_\theta(\cdot\mid s)$ ว่า **"ตัวการแจกแจง"** และบางที่เรียก
> ให้เห็นภาพว่า **"ก้อนหมอกความน่าจะเป็น"** (ระฆังทั้งอันที่คลุมทุกค่าของ $a$) ·
> สองคำนี้หมายถึงสิ่งเดียวกัน คือ object ในตารางข้างบน

**จุดกลมคือช่องว่างที่ยังไม่ได้เติม** — เป็นสัญลักษณ์ที่บอกว่า *"ยังไม่ได้กดปุ่ม ยังไม่มีกาแฟ
ออกมา นี่คือตัวเครื่องนะ"*

> **$\pi_\theta$ ไม่ใช่ NN** — NN คายแค่ $\mu$ · $\pi_\theta$ = NN + $\sigma$ + รูประฆัง
> `logstd` เป็น `nn.Parameter` แยกต่างหาก ไม่ได้ออกมาจาก NN เลย
> ([actor_critic.py:118](../tron1-rl-isaaclab/rsl_rl/rsl_rl/modules/actor_critic.py#L118))

| เขียนว่า | $a$ อยู่ตรงไหน · แปลว่าอะไร | คืนอะไร | shape | โค้ด |
| --- | --- | --- | --- | --- |
| $\mu_\theta(s)$ | ไม่มี $a$ เลย — สูตรนี้ไม่เกี่ยวกับ $a$ | เวกเตอร์ค่ากลาง | `(B,8)` | `self.actor(obs)` |
| $\pi_\theta(\cdot \mid s)$ | ไม่มี $a$ — วงเล็บว่าง (จุดกลม) | **object** ไม่ใช่ตัวเลข | — | `Normal(mean, std)` |
| $a \sim \pi_\theta(\cdot \mid s)$ | $a$ อยู่ **หน้าเครื่องหมาย $\sim$** → $a$ คือ**ผลลัพธ์**ที่ไหลออกมา | action จริง | `(B,8)` | `.sample()` |
| $\pi_\theta(a \mid s)$ | $a$ อยู่ **ในวงเล็บ** → $a$ คือ**สิ่งที่เราป้อนเข้าไปถาม** | **scalar** | `(B,)` | `.log_prob(a).sum(-1)` |

> **กฎจากตำแหน่งของ $a$** — อยู่หน้า $\sim$ แปลว่า *ยังไม่มี $a$ กำลังจะสร้างมันขึ้นมา* ·
> อยู่ในวงเล็บแปลว่า *มี $a$ อยู่แล้ว กำลังเอาไปถามคำถามกับมัน* · ลำดับเวลาจึงเป็น
> `.sample()` ก่อนเสมอ แล้วค่อย `.log_prob(a)`

**$\sim$ ไม่ใช่การเรียกฟังก์ชัน — และนี่ไม่ใช่ "ฟังก์ชันเดียวที่คืนค่าได้สองแบบ"**

สองบรรทัดล่างของตารางหน้าตาใกล้กันมากจนดูเหมือนเป็นฟังก์ชันเดียวกันที่คืนค่าได้สองแบบ
(แบบหนึ่งสุ่มให้ $a$ อีกแบบรับ $a$ แล้วคืนความหนาแน่น) — **ไม่ใช่** ใช้นิยามของคำว่า
ฟังก์ชันตัดสินได้เลย:

> ฟังก์ชัน = *input เดิม ต้องได้ output เดิมเสมอ*

`.sample()` ละเมิดข้อนี้เต็ม ๆ — เรียกสองครั้งด้วย $s$ เดิมเป๊ะ ได้คนละคำตอบ **มันจึงไม่ใช่
การเรียกฟังก์ชันตั้งแต่แรก** และนั่นคือเหตุผลที่สัญกรณ์ใช้ $\sim$ ไม่ใช่ $=$

สิ่งที่เกิดขึ้นจริงคือ `dist` เป็น**วัตถุที่ถือตัวเลขสองตัว** ($\mu$ กับ $\sigma$) แล้วมี
**ปฏิบัติการหลายอย่าง** ที่หยิบตัวเลขคู่นั้นไปใช้คนละแบบ:

| ปฏิบัติการ | สัญกรณ์ | ต้องมีวัตถุดิบเพิ่ม | คืนอะไร | สุ่มไหม |
| --- | --- | --- | --- | --- |
| ประเมินความหนาแน่น | $\pi_\theta(a\mid s)$ | ค่า $a$ | scalar | ไม่ — $a$ เดิมได้เลขเดิมเสมอ |
| สุ่ม | $a \sim \pi_\theta(\cdot\mid s)$ | **เลขสุ่ม $\varepsilon$** | action `(8,)` | ใช่ |
| ความกว้าง | $H[\pi_\theta(\cdot\mid s)]$ | — | scalar | ไม่ |
| ค่ากลาง | `.mean` | — | `(8,)` | ไม่ |

ดูคอลัมน์ **"ต้องมีวัตถุดิบเพิ่ม"** — การสุ่มต้องการของที่**ไม่ได้อยู่ใน $\mu, \sigma$** เลย คือ
เลขสุ่ม $\varepsilon$ · ในโค้ด `sample()` ไปหยิบมันจากเครื่องสุ่มของ PyTorch เอง
(`torch.normal`) — ถ้าล็อก seed ไว้ ผลจะซ้ำเดิมทันที ซึ่งพิสูจน์ว่ามี input ที่มองไม่เห็น
ซ่อนอยู่จริง พอตรึง input ตัวนั้น มันก็กลายเป็นฟังก์ชันปกติ

**อุปมาที่ไม่พัง — ลูกเต๋าถ่วงน้ำหนัก**

| ในอุปมา | สัญกรณ์ | ใน Tron1 จริง |
| --- | --- | --- |
| ตารางความน่าจะเป็นของลูกเต๋า | $\pi_\theta(\cdot\mid s)$ | ระฆัง $\mathcal{N}(0.42,\ 0.5)$ |
| **ทอย** แล้วออกหน้า 6 · ทอยใหม่ได้คนละหน้า | $a \sim \pi_\theta(\cdot\mid s)$ | สุ่มได้ $a = 0.61$ |
| **เปิดตารางดู** ว่าหน้า 6 มีโอกาสเท่าไร · เปิดกี่ครั้งก็ได้เลขเดิม | $\pi_\theta(a{=}6\mid s)$ | $\pi_\theta(0.61\mid s) = 0.7423$ |

ทั้งสองอย่างใช้ตารางใบเดียวกันแต่เป็นคนละกิจกรรม และ**ไม่มีการ "ยัดหน้า 6 กลับเข้าไป
ในลูกเต๋า"** เพราะการเปิดตารางดูไม่ได้ทำอะไรกับลูกเต๋าเลย แค่อ่านค่าจากกระดาษ

**เลข 6 ในแถวล่างคือค่า $a$ นั่นเอง** — จะถามหน้าไหนก็ได้ ตารางมีค่าให้ทุกหน้า และไม่ต้อง
ทอยก่อนด้วยซ้ำ · แต่ **PPO เลือกถามหน้าที่ทอยได้จริงเสมอ** เพราะคำถามที่ต้องการคำตอบคือ
*"policy ชอบ action ที่มันเล่นไปจริง ๆ แค่ไหน"* — ค่า $a$ ที่ป้อนเข้าไปจึงมาจาก buffer ตลอด
(ดู E12)

> **ข้อจำกัดของอุปมานี้** — ลูกเต๋ามี 6 หน้านับได้ ส่วน action ของ Tron1 เป็นจำนวนจริง
> ต่อเนื่อง · ค่าที่เปิดตารางลูกเต๋าได้คือ **ความน่าจะเป็น** (รวมทุกช่อง $= 1$ เกิน 1 ไม่ได้)
> ส่วนของ Gaussian คือ **ความหนาแน่น** (พื้นที่ใต้กราฟ $= 1$ แต่ตัวค่า **เกิน 1 ได้** เช่น
> $\sigma = 0.25$ ยอดระฆังสูง $1.596$ — โน้ต 05 §2.3) · ใช้ลูกเต๋าแทน "ทอย vs เปิดตารางดู"
> ได้ แต่ห้ามลากไปสรุปเรื่องขนาดของค่า
>
> และอุปมาเครื่องชงกาแฟข้างบนใช้ได้เฉพาะความต่างระหว่าง *ตัวเครื่อง* กับ *ของที่ออกมา*
> ($f$ กับ $f(x)$) เท่านั้น · ใช้กับเรื่องสุ่ม-vs-ประเมินไม่ได้ เพราะไม่มีใครเอากาแฟยัด
> กลับเข้าเครื่อง

**เครื่องหมาย $=$ ในบรรทัด $\pi_\theta(\cdot\mid s) = \mathcal{N}(\mu,\sigma)$ แปลว่าอะไร**

จุดที่สะดุดกันมากที่สุดคือ "สองข้างเป็นวัตถุคนละอย่างกัน แล้วเท่ากันได้ยังไง" —
คำตอบคือ **มันเป็นวัตถุชนิดเดียวกัน** ทั้งคู่:

| | ข้างซ้าย $\pi_\theta(\cdot \mid s)$ | ข้างขวา $\mathcal{N}(\mu, \sigma)$ |
| --- | --- | --- |
| เป็นวัตถุชนิดอะไร | ฟังก์ชัน $\mathbb{R}^8 \to \mathbb{R}_{\ge 0}$ | ฟังก์ชัน $\mathbb{R}^8 \to \mathbb{R}_{\ge 0}$ |
| รับอะไร | action หนึ่งชุด | action หนึ่งชุด |
| คืนอะไร | ความหนาแน่น (เลขตัวเดียว) | ความหนาแน่น (เลขตัวเดียว) |
| มาจากไหน | "สิ่งที่ policy คายออกมาตอนอยู่ที่ $s$" | "สูตรระฆังที่มีพารามิเตอร์ $\mu,\sigma$" |

ทั้งคู่เป็นสมาชิกของเซตเดียวกัน คือเซตของการแจกแจงบน $\mathbb{R}^8$ — พอเป็นสมาชิก
เซตเดียวกัน ก็ใส่เครื่องหมายเท่ากับได้ตามปกติ เหมือนเขียน $f = g$ สำหรับฟังก์ชันสองตัว

**$=$ ระหว่างฟังก์ชัน แปลว่า "เท่ากันที่ทุกจุด input"** ถ้าเขียนไม่ย่อคือ

$$\pi_\theta(a \mid s) = \mathcal{N}(a;\ \mu,\ \sigma) \qquad \textbf{สำหรับ } a \textbf{ ทุกค่าที่เป็นไปได้}$$

ตรวจด้วยตัวเลขได้ ($\mu = 0.42$, $\sigma = 0.5$, ดูมิติเดียว):

| ป้อน $a$ | ข้างซ้ายให้ | ข้างขวาให้ |
| --- | --- | --- |
| $0.61$ | $0.7423$ | $0.7423$ |
| $0.42$ | $0.7979$ | $0.7979$ |
| $1.50$ | $0.0774$ | $0.0774$ |

**ซ้ายคือ "ตำแหน่ง" ขวาคือ "คนที่มานั่งตำแหน่งนั้น"** — เหมือนประโยค *"ผู้จัดการฝ่ายขาย
= สมชาย"* ซึ่งเท่ากันได้เพราะทั้งสองข้างชี้ไปที่คนคนเดียวกัน · ข้างซ้ายบอก **บทบาท**
("ตัวแจกแจงที่ policy ใช้เลือก action ตอนอยู่ที่ $s$" — ยังไม่บอกว่าหน้าตายังไง) ข้างขวา
บอก **ตัวจริงที่มารับบทนั้น** (ระฆังที่มีพารามิเตอร์สองตัว)

**และนี่คือประเด็นสำคัญที่สุด: สมการนี้ไม่ได้พิสูจน์มา แต่เป็นการ *เลือก* ของคนออกแบบ**
ไม่มีกฎธรรมชาติข้อไหนบังคับว่า policy ต้องเป็นเกาส์เซียน — ทีม rsl_rl ตัดสินใจให้มันเป็น
แล้วเขียนลงโค้ด ถ้าเลือกอย่างอื่นก็ได้:

| ถ้าเลือก… | สมการจะเป็น | ใช้เมื่อไหร่ |
| --- | --- | --- |
| เกาส์เซียน | $\pi_\theta(\cdot\mid s) = \mathcal{N}(\mu, \sigma)$ | action ต่อเนื่อง ไม่มีขอบ ← **Tron1 ใช้อันนี้** |
| Beta | $\pi_\theta(\cdot\mid s) = \text{Beta}(\alpha, \beta)$ | action มีขอบชัด เช่น $[-1,1]$ |
| Categorical | $\pi_\theta(\cdot\mid s) = \text{Cat}(p_1,\dots,p_k)$ | action เป็นตัวเลือก เช่นเกม Atari |
| Tanh-Normal | $\pi_\theta(\cdot\mid s) = \tanh\big(\mathcal{N}(\mu,\sigma)\big)$ | SAC ใช้ |

ข้างซ้ายเหมือนกันหมด ข้างขวาต่างกัน — **ข้างซ้ายคือ interface ข้างขวาคือ implementation**

**แล้วทำไมต้องมีระฆัง — ทำไมไม่เทรนให้ NN คาย action ออกมาตรง ๆ**

คำถามนี้มีสองชั้น และชั้นที่สองคือเหตุผลจริง

**ชั้นที่ 1 · NN สุ่มไม่ได้ — nonlinear ไม่ใช่ random**

ความไม่เชิงเส้นกับความสุ่มเป็นคนละเรื่องกันสิ้นเชิง:

| ความสามารถ | NN มีไหม | ได้มาจากไหน |
| --- | --- | --- |
| แปลง input เป็น output ที่ซับซ้อนแค่ไหนก็ได้ | **มี** (universal approximation) | ELU + หลายชั้น |
| ให้คำตอบต่างกันเมื่อ input เหมือนเดิม | **ไม่มี** | ต้องมี RNG จากข้างนอกเท่านั้น |

ELU ไม่ได้สร้างความสุ่ม มันแค่ทำให้เส้นโค้งงอได้ · ป้อน $s$ เดิมเข้า NN พันครั้ง ได้เลขเดิม
เป๊ะพันครั้ง — นี่คือนิยามของ deterministic function · ดังนั้น "ให้ NN คาย action ตรง ๆ"
= deterministic policy = ทำ action เดียวต่อ state = ไม่มีการสำรวจ

**ชั้นที่ 2 · PPO ต้องการ *ตัวเลข* $\pi(a\mid s)$ ไม่ใช่แค่ action**

สมมติมีกล่องดำที่คาย action สุ่มได้เองโดยไม่ต้องมีระฆัง — PPO ก็ยังใช้ไม่ได้อยู่ดี:

| สมการ | ถ้าไม่มีระฆัง |
| --- | --- |
| E6 สุ่ม action | กล่องดำทำได้ ✓ |
| E7–E8 ความหนาแน่น | **คำนวณไม่ได้** ไม่รู้สูตร ✗ |
| E9 $\log\pi(a\mid s)$ | **ไม่มี** ✗ |
| E13 $\rho = \pi_{\text{new}}/\pi_{\text{old}}$ | **เขียนไม่ได้** ✗ |
| E14 $L^{CLIP}$ | **ไม่มี loss ให้ backward** ✗ |

> **เหตุผลจริง** — เราไม่ได้เลือก Gaussian เพราะอยากได้ความสุ่ม (ความสุ่มหาที่ไหนก็ได้
> ถูกมาก) แต่เลือกเพราะมันเป็นตัวสุ่มที่ **ย้อนกลับไปคำนวณได้ว่าโอกาสที่จะสุ่มได้แบบนี้
> มีเท่าไร** ในสูตรปิดสามพจน์

Gaussian ให้สองอย่างพร้อมกัน ซึ่งหายาก — และทั้งคู่เป็นแค่บวกลบคูณหาร จึงทำ
49,152 × 20 ครั้งต่อ iteration ไหว:

$$\underbrace{a = \mu + \sigma\varepsilon}_{\text{สุ่มง่ายมาก}} \qquad\qquad \underbrace{\log\pi = -\tfrac{(a-\mu)^2}{2\sigma^2} - \log\sigma - 0.919}_{\text{ประเมินย้อนหลังง่ายมาก}}$$

**แล้วความสามารถ nonlinear ของ NN ถูกใช้เต็มที่ไหม — เต็มที่อยู่แล้ว**

$$\pi_\theta(\cdot\mid s) = \mathcal{N}\big(\underbrace{\mu_\theta(s)}_{\textbf{ตรงนี้ nonlinear เต็มรูปแบบ}},\ \sigma\big)$$

ระฆังไม่ได้จำกัดความซับซ้อนของการตัดสินใจเลย มันจำกัดแค่รูปทรงของ*การกระจายรอบ ๆ
คำตอบ* · เทียบเป็นภาพ: มือปืนที่เล็งเก่งมาก (NN คิดซับซ้อน) แต่กระสุนกระจายรอบเป้า
เป็นวงกลม (Gaussian) — ความเก่งอยู่ที่การเล็ง ไม่ได้อยู่ที่รูปทรงการกระจาย

**ทางเลือกอื่นที่มีจริงในวงการ**

| แนวทาง | ทำยังไง | ทำไม Tron1 ไม่ใช้ |
| --- | --- | --- |
| NN คาย $\sigma$ ด้วย | output 16 ตัว (8 $\mu$ + 8 $\log\sigma$) | ทำได้จริง หลายงานทำ · rsl_rl เลือกไม่ทำเพราะเทรนนิ่งกว่า |
| Deterministic + noise ข้างนอก | DDPG / TD3 | คำนวณ $\rho$ ไม่ได้ → ต้องเปลี่ยนไปใช้ off-policy + Q-function ทั้งระบบ |
| หั่น action เป็นช่วง ๆ | Categorical — NN คาย logits แล้วสุ่ม | 8 ข้อ × k ระดับ = ทางเลือกระเบิด และเสียความต่อเนื่องของมุมข้อ |
| Normalizing flow | คาย action ตรง ๆ และคำนวณ density ได้ด้วย | แพงกว่ามาก เกินจำเป็นสำหรับ locomotion |

แถวที่สองคือ "ให้ NN คาย action ตรง ๆ" ของจริง — มีคนทำ แต่ต้องทิ้ง PPO ทั้งตัวแล้ว
เปลี่ยนไปใช้อัลกอริทึมคนละตระกูล

**สรุป — อะไรตายตัว อะไรถูกเรียน**

จุดที่คนสรุปผิดบ่อยที่สุดคือคิดว่า *"เทรนไปเรื่อย ๆ จนมันกลายเป็น normal distribution"* —
**ไม่ใช่** · มันเป็น normal ตั้งแต่วินาทีแรกที่รันโค้ด และเป็น normal ตลอดไปจนวินาทีสุดท้าย
เพราะรูปทรงระฆังไม่ได้มาจากการเรียน แต่มาจากบรรทัด `Normal(...)` ที่คนเขียนไว้ตายตัว
สิ่งที่เรียนคือ **ระฆังใบนั้นควรวางตรงไหน และควรแคบแค่ไหน**

| | ตายตัวตั้งแต่แรก (คนออกแบบเลือก) | ถูกเรียน (Adam ปรับ) |
| --- | --- | --- |
| **รูปทรง** = ระฆัง Gaussian | ✓ ไม่มีวันเปลี่ยน | — |
| **จำนวนมิติ** = 8 | ✓ | — |
| **$\sigma$ ไม่ขึ้นกับ $s$** | ✓ (เป็นการออกแบบ) | — |
| **ตำแหน่งระฆัง** $\mu_\theta(s)$ | — | ✓ ผ่าน weight 187,272 ตัว |
| **ความกว้าง** $\sigma$ | — | ✓ ผ่าน `logstd` 8 ตัว |

สองแถวล่างถูกฝึกด้วย Adam ตัวเดียวกัน — `optim.Adam(self.actor_critic.parameters())`
ที่ [ppo.py:85](../tron1-rl-isaaclab/rsl_rl/rsl_rl/algorithm/ppo.py#L85) ครอบทั้ง NN และ `logstd`
(encoder มี optimizer แยกที่บรรทัด 88)

| | ระฆังหน้าตายังไง |
| --- | --- |
| **iteration 0** | เป็นระฆังเรียบร้อยแล้ว แต่**วางผิดที่** (weight มั่ว) และ**กว้างสุด** ($\sigma = 1.0$ เพราะ `logstd = 0`) |
| **ระหว่างเทรน** | ค่อย ๆ เลื่อนไปวางถูกที่มากขึ้นสำหรับแต่ละ $s$ และค่อย ๆ **แคบลง** (ดู `mean_noise_std` ใน tensorboard) |
| **ตอน deploy** | ไม่สร้างระฆังแล้ว ใช้แต่จุดกลาง $\mu$ |

> **และอย่าลืมว่า $\pi_\theta$ กับ $\pi_\theta(\cdot\mid s)$ คนละอย่างกัน** — $\pi_\theta$ คือ *policy
> ทั้งอัน* (เครื่องที่รับ state ใดก็ได้แล้วคายระฆังออกมา) ส่วน $\pi_\theta(\cdot\mid s)$ คือ
> *ระฆังหนึ่งใบ* ที่ได้จากการป้อน $s$ เข้าไป · หุ่นยืนท่าหนึ่งได้ระฆังใบหนึ่ง ขยับไปอีกท่า
> ได้อีกใบ — policy เดียวกัน แต่คนละระฆัง

**แล้ว $s$ หายไปไหนในข้างขวา** — ซ่อนอยู่ใน $\mu$ เขียนเต็มไม่ย่อคือ

$$\pi_\theta(\cdot \mid s) = \mathcal{N}\big(\underbrace{\mu_\theta(s)}_{s \text{ อยู่ตรงนี้}},\ \underbrace{\sigma_\theta}_{\text{ไม่มี } s}\big)$$

$s$ เปลี่ยน → $\mu$ เปลี่ยน → ระฆังย้ายตำแหน่ง → ได้การแจกแจงคนละตัว · ส่วน $\sigma$ ไม่มี $s$
อยู่ในนั้น ระฆังจึงกว้างเท่าเดิมเสมอไม่ว่าจะอยู่ state ไหน

> **$=$ ตัวนี้คือ `=` ตัวเดียวกับในโค้ดเป๊ะ ๆ** — `self.distribution = Normal(mean, std)`
> ทั้งสองที่หมายถึง "ฝั่งขวาสร้างวัตถุขึ้นมา แล้วให้ชื่อฝั่งซ้ายชี้ไปที่มัน" เรียกว่า
> *definitional equality* (นิยามให้เท่า) ไม่ใช่ *derived equality* (พิสูจน์ได้ว่าเท่า) ·
> บางตำราจึงเขียน $:=$ หรือ $\triangleq$ เพื่อย้ำจุดนี้

**ทำไมตำรานิยมเขียนรูปย่อ — มันไม่ได้ย่อเพื่อประหยัดที่ แต่พูดคนละเรื่อง**

| | รูปเต็ม $\pi_\theta(a\mid s) = \mathcal{N}(a;\mu,\sigma)$ | รูปย่อ $\pi_\theta(\cdot\mid s) = \mathcal{N}(\mu,\sigma)$ |
| --- | --- | --- |
| พูดถึง | **ค่า** ณ จุด $a$ จุดหนึ่ง | **ตัวการแจกแจง** ทั้งอัน |
| เป็นประโยคว่า | "ที่จุดนี้ ความสูงเท่ากัน" | "policy **คือ** ระฆังอันนี้" |
| ทำอะไรต่อได้ | เอาเลขไปคำนวณ | สุ่มจากมัน · หา entropy · หา KL |

เหตุผลจริงคือ **มีคำถามหลายอย่างที่ถามกับค่าจุดเดียวไม่ได้** — สามสมการนี้ใช้จริงในโค้ด
Tron1 และทุกอันต้องการตัวการแจกแจงทั้งอัน:

$$a \sim \pi_\theta(\cdot\mid s) \qquad H\big[\pi_\theta(\cdot\mid s)\big] \qquad D_{KL}\big(\pi_{\theta_{old}}(\cdot\mid s)\ \|\ \pi_{\theta_{new}}(\cdot\mid s)\big)$$

- **สุ่ม** — ต้องมีระฆังทั้งอันก่อน ถ้ามีแค่ "ความสูงที่ $a = 0.61$" สุ่มไม่ได้
- **entropy** — "ระฆังนี้กว้างแค่ไหน" เป็นสมบัติของระฆังทั้งอัน จุดเดียวตอบไม่ได้
- **KL** — "สองระฆังนี้ต่างกันแค่ไหน" ต้องมีสองตัวมาเทียบ

เป็นเหตุผลเดียวกับที่เราพูดว่า *"กราฟของ $f$ เป็นพาราโบลา"* แทนที่จะไล่บอกความสูงทีละจุด
— สิ่งที่ต้องการพูดเป็นประโยคระดับ*ตัวเครื่อง* ไม่ใช่ระดับจุด · และมันตรงกับโค้ดพอดี:
สร้างตัวการแจกแจงครั้งเดียว แล้วถามหลายคำถามกับตัวเดิม

```python
dist = Normal(mean, std)        # ← รูปย่อ : สร้างตัวการแจกแจงครั้งเดียว
dist.sample()                   # ↘
dist.log_prob(a).sum(-1)        #  ↘ เติมจุดกลมด้วยคำถามต่าง ๆ กัน
dist.entropy().sum(-1)          # ↗
```

> **กฎอ่านที่ใช้ได้ทันที** — เจอ $\cdot$ ในวงเล็บ ให้แปลว่า *"ตัวการแจกแจงทั้งอัน"* แล้วมองหา
> ว่าประโยคนั้นจะเอามันไปทำอะไร (สุ่ม? วัดความกว้าง? เทียบกับตัวอื่น?) · เจอตัวแปรจริงในวงเล็บ
> ให้แปลว่า *"เลขตัวเดียว"*
>
> **ตั้งแต่นี้เป็นต้นไป โน้ตนี้ใช้รูปย่อทั้งหมด** — ถ้าสะดุดตรงไหน ให้กางเป็นรูปเต็ม
> ในหัวแล้วเติมคำว่า "สำหรับ $a$ ทุกค่า" ต่อท้าย

### 3.5.3 สองทิศทางที่ต้องแยกให้ออก

**ทิศ ① $\mu_\theta(s) \Rightarrow \pi_\theta$ — ประกอบร่าง (มีการคำนวณ)** ต้องมี $\sigma$ มาสมทบ
จึงจะได้ $\pi$ · เกิดที่ [actor_critic.py:155-157](../tron1-rl-isaaclab/rsl_rl/rsl_rl/modules/actor_critic.py#L155-L157)

**ทิศ ② $\pi_\theta \Rightarrow \mu_\theta(s)$ — อ่านฉลาก (ไม่มีการคำนวณ)** เพราะ $\mu$ คือ
พารามิเตอร์ตัวที่หนึ่งของ $\pi$ อยู่แล้ว `action_mean` คือ `return self.distribution.mean`
ซึ่งใน torch คือ `return self.loc` — tensor ตัวเดิมเป๊ะ

**ทิศ ③ $\pi_\theta \Rightarrow \pi_\theta(a\mid s)$ — ประเมินค่า (ต้องมี $a$ ก่อน)** เอา $a$ หย่อนกลับ
เข้าสูตรระฆัง ได้ scalar · เกิดที่ [actor_critic.py:163-164](../tron1-rl-isaaclab/rsl_rl/rsl_rl/modules/actor_critic.py#L163-L164)

> เปรียบเทียบ: $\mu, \sigma$ คือ**ส่วนผสม** · $\pi$ คือ**ขนมที่อบแล้ว** · ทิศ ① คืออบ ·
> ทิศ ② คือแกะฉลากดูว่าใส่อะไรไป — ไม่ใช่การแยกขนมกลับเป็นแป้งกับไข่ ·
> ทิศ ③ คือชิมแล้วให้คะแนนชิ้นที่หยิบมา

**E6 · สุ่ม**

$$\underbrace{a \sim \pi_\theta(\cdot \mid s)}_{\text{ประโยคที่ 1}} \qquad \underbrace{\Longleftrightarrow}_{\text{ตัวเชื่อม}} \qquad \underbrace{a = \mu + \sigma \odot \varepsilon,\quad \varepsilon \sim \mathcal{N}(0, I_8)}_{\text{ประโยคที่ 2}}$$

**อ่านสมการนี้ทีละเครื่องหมาย**

บรรทัดนี้คือ **ประโยคสองประโยคที่พูดเรื่องเดียวกัน** วางคู่กันเพื่อบอกว่าสองอันนี้เหมือนกัน

| เครื่องหมาย | ชื่อ | อ่านว่า | ไม่ใช่ |
| --- | --- | --- | --- |
| $\sim$ | tilde | **"ถูกสุ่มออกมาจาก"** | ไม่ใช่ "ประมาณเท่ากับ" |
| $\cdot$ | จุดกลาง | **ช่องว่างที่ยังไม่เติม** = ตัวการแจกแจงทั้งอัน (§3.5.2) | ไม่ใช่เครื่องหมายคูณ |
| $\mid$ | ขีดตั้ง | **"โดยมีเงื่อนไขว่า"** (§3.5.1) | ไม่ใช่คอมมา |
| $\Longleftrightarrow$ | ลูกศรสองหัว | **"ก็คือ / เทียบเท่ากัน"** | **ไม่ใช่ทิศทางการไหลของข้อมูล** |
| $\odot$ | Hadamard | **คูณทีละตัวตรงตำแหน่ง** — ในโค้ดคือ `*` เฉย ๆ | ไม่ใช่ dot product ไม่ใช่คูณเมทริกซ์ |
| $\mathcal{N}(0, I_8)$ | — | เกาส์เซียนกลาง $0$ กว้าง $1$ **8 ตัวที่อิสระต่อกัน** | — |

**ลูกศร $\Longleftrightarrow$ ไม่ได้ชี้ไปกลับ** — มันไม่มีทิศทางในความหมายของ "ค่าไหลจากซ้ายไปขวา"
แต่เป็นตัวเชื่อมประโยคแบบเดียวกับคำว่า *"ก็คือ"* ในภาษาไทย เช่น "ฝนตก $\Longleftrightarrow$
พื้นเปียก" = สองอย่างนี้จริงพร้อมกันเสมอ ไม่ได้แปลว่าฝนวิ่งไปหาพื้นแล้ววิ่งกลับ

| ลูกศร | ความหมาย | ตัวอย่างในโน้ตนี้ |
| --- | --- | --- |
| $\rightarrow$ | "กลายเป็น / ไปยัง" | `(B,42)` → `(B,8)` |
| $\longrightarrow$ | "ถูกส่งไปเก็บที่" | E10 |
| $\leftarrow$ | "ถูกกำหนดค่าใหม่เป็น" (assignment) | $\theta \leftarrow \theta - \alpha\nabla L$ |
| $\Longleftrightarrow$ | **"ก็คือ / เทียบเท่ากับ"** | E6 บรรทัดนี้ |

**ทำไมเขียนสองแบบ**

| ประโยคที่ 1 · $a \sim \pi_\theta(\cdot\mid s)$ | ประโยคที่ 2 · $a = \mu + \sigma \odot \varepsilon$ |
| --- | --- |
| บอก **"คืออะไร"** — $a$ คือของที่สุ่มมาจากการแจกแจงนี้ | บอก **"ทำยังไง"** — เอา $\mu$ บวกด้วย $\sigma$ คูณเลขสุ่ม |
| ภาษาคณิตศาสตร์ | สูตรที่คอมพิวเตอร์รันได้จริง |

**$\odot$ ทำงานยังไง — ดูด้วยตัวเลข 3 มิติ (ของจริง 8)**

$$\begin{aligned} \mu &= [\,0.42,\ -0.31,\ 0.05\,] \\ \sigma &= [\,0.5,\ \ \ \ \ 0.5,\ \ \ \ 0.5\,] \\ \varepsilon &= [\,0.38,\ -0.12,\ 0.91\,] \quad \leftarrow \text{สุ่มใหม่ทุกครั้ง} \end{aligned}$$

$$\sigma \odot \varepsilon = [\,0.5{\times}0.38,\ \ 0.5{\times}(-0.12),\ \ 0.5{\times}0.91\,] = [\,0.19,\ -0.06,\ 0.455\,]$$

$$a = \mu + (\sigma\odot\varepsilon) = [\,0.61,\ -0.37,\ 0.505\,]$$

ตรงกับสามแถวแรกของตารางใน §3.5.5 พอดี

> ถ้าเป็น dot product ผลลัพธ์จะเป็นเลขตัวเดียว ($0.19 - 0.06 + 0.455 = 0.585$) ซึ่งผิด
> เพราะเราต้องการ action 8 ค่า ไม่ใช่ค่าเดียว — นี่คือเหตุผลที่ต้องใช้ $\odot$ ไม่ใช่ $\cdot$

**$I_8$ บอกอะไร** — ช่องที่สองของ $\mathcal{N}$ ในโลกหลายมิติคือ *เมทริกซ์ความแปรปรวนร่วม*
ไม่ใช่ตัวเลขเดี่ยว อ่านได้สองอย่าง:

- **เส้นทแยงเป็น 1 ทั้งหมด** → ทุกมิติกว้างเท่ากัน (sd = 1)
- **นอกเส้นทแยงเป็น 0 ทั้งหมด** → **แต่ละมิติสุ่มอิสระจากกัน** ข้อ 3 จะสุ่มได้เท่าไร
  ไม่เกี่ยวกับข้อ 1 เลย

**อ่านทั้งบรรทัดเป็นประโยคเดียว** — *"action ที่จะเล่นจริง ได้จากการสุ่มออกมาจากก้อนหมอก

โดยสุ่มแยกกัน 8 ครั้ง ครั้งละข้อ"*

> **หมายถึงอะไร** — หยิบท่าจริงออกมาจากก้อนหมอก
>
> **ทำไปทำไม** — ถ้าเล่นแต่ท่าที่คิดว่าดีที่สุด จะไม่มีวันรู้ว่ามีท่าที่ดีกว่า · gradient ของ PPO

```python
def sample(self, sample_shape=torch.Size()):
    shape = self._extended_shape(sample_shape)
    with torch.no_grad():                                          # ★
        return torch.normal(self.loc.expand(shape), self.scale.expand(shape))
```

`no_grad` บรรทัดนี้สำคัญมาก: **$a$ ไม่มีสายกลับไปหา $\theta$** gradient ไหลผ่าน $a$ ไม่ได้เลย
— นี่คือเหตุผลทั้งหมดที่ PPO ต้องมี $\rho$ ถ้าอยากให้ไหลได้ต้องใช้ `rsample()`
(`normal.py:75-78`, $a = \mu + \sigma\varepsilon$ แบบ reparameterization) ซึ่ง rsl_rl **ไม่ได้ใช้**

**ตอน deploy ไม่ใช่การตั้ง $\sigma = 0$ — แต่คือการข้ามบรรทัดนี้ทั้งบรรทัด**

ผลลัพธ์เหมือนกัน ($a = \mu + 0 \odot \varepsilon = \mu$) จึงเป็นภาพในหัวที่ถูก แต่กลไกต่างกัน

**และตั้ง $\sigma = 0$ จริง ๆ ไม่ได้ด้วย** เพราะสูตรความหนาแน่นระเบิดทันที — พจน์แรกหาร
ด้วย $\sigma^2 = 0$ และพจน์ที่สองเป็น $\log 0 = -\infty$ · $\mathcal{N}(\mu, 0)$ ไม่ใช่การแจกแจง
ที่เขียนเป็นความหนาแน่นได้ (มันคือเข็มแหลม Dirac) พูดให้ถูกคือ deploy เป็น**ลิมิต**
$\sigma \to 0$ ไม่ใช่การแทนค่า

> **ทำไมคืน $\mu$ แล้วสบายใจได้** — สำหรับ Gaussian *ค่าเฉลี่ย = ฐานนิยม = จุดที่ความ
> หนาแน่นสูงสุด* เป็นจุดเดียวกันหมด การคืน $\mu$ จึงแปลว่า "เล่น action ที่ policy คิดว่า
> น่าจะเป็นที่สุด" พอดี · ถ้าใช้การแจกแจงที่เบ้ (เช่น tanh-normal ของ SAC) สองอย่างนี้
> จะคนละจุด แล้วต้องเลือกว่าจะเอาอันไหน

#### ช่วง C — จาก $\pi_\theta$ ไปเป็น $\pi_\theta(a\mid s)$ — ทิศ ③

*ประโยคเดียวของช่วงนี้: จากการกระทำ → ตัวเลขที่บอกว่า "ตอนนั้นเราชอบมันแค่ไหน" เก็บไว้เทียบทีหลัง*

**E7 · ความหนาแน่นรายมิติ**

$$\mathcal{N}(a_i;\mu_i,\sigma_i) = \frac{1}{\sigma_i\sqrt{2\pi}}\exp\!\left(-\frac{(a_i-\mu_i)^2}{2\sigma_i^2}\right)$$

> **หมายถึงอะไร** — "ถ้าเล่นซ้ำอีกครั้ง โอกาสที่จะได้ค่าประมาณนี้อีก หนาแน่นแค่ไหน" ·
> สูงเมื่อ $a$ ใกล้ $\mu$ ต่ำเมื่อไกล
>
> **ทำไปทำไม** — PPO ทั้งอัลกอริทึมตั้งอยู่บนการเทียบ "ชอบเท่าไรตอนเก็บข้อมูล vs ชอบ
> เท่าไรตอนนี้" · ต้องมีมาตรวัดความชอบก่อน ถึงจะเทียบได้
>
> **ระวัง** — มันคือความ*หนาแน่น* ไม่ใช่ความน่าจะเป็น ค่าเกิน 1 ได้ (โน้ต 05 §2.3)

**E8 · เข้า log แล้วแตกเป็นสามพจน์ — นี่คือสิ่งที่ torch คำนวณจริง**

$$\log \mathcal{N}(a_i) = \underbrace{-\frac{(a_i-\mu_i)^2}{2\sigma_i^2}}_{\text{พจน์ระยะห่าง}} \;\underbrace{-\ \log\sigma_i}_{\text{พจน์ความกว้าง}} \;\underbrace{-\ \tfrac{1}{2}\log 2\pi}_{=\,-0.9189\ \text{เสมอ}}$$

รับ $a$ `(B,8)` + object → คืน `(B,8)` **ยังไม่ยุบ** · `torch/distributions/normal.py:88-92`

> **หมายถึงอะไร** — สมการเดียวกับ E7 เป๊ะ ๆ แค่มองในโลก log
>
> **ทำไมต้อง log — สามเหตุผล**
>
> 1. คูณเลขที่น้อยกว่า 1 แปดตัว ได้ค่าเล็กจนคอมพิวเตอร์ปัดเป็นศูนย์ (underflow) · log
>    แปลงการคูณเป็นการบวก ปัญหาหายไป
> 2. การ**หาร**ใน $\rho$ (E13) กลายเป็นการ**ลบ** ซึ่งเสถียรกว่ามาก
> 3. อนุพันธ์ออกมาสั้นและสวย — E15 หน้าตาเรียบง่ายได้เพราะบรรทัดนี้
>
> **อ่านสามพจน์** — พจน์ 1 = ลงโทษตามระยะห่างกำลังสอง · พจน์ 2 = ยิ่งกล้าลอง
> ($\sigma$ ใหญ่) ยิ่งไม่มีทางหนาแน่น · พจน์ 3 = ค่าคงที่ **ไม่มีผลต่อ gradient เลย**

```python
var = self.scale**2                                  #  σ²
log_scale = self.scale.log()                         #  log σ
return (
    -((value - self.loc) ** 2) / (2 * var)           #  −(a−μ)² / 2σ²        พจน์ 1
    - log_scale                                      #  − log σ              พจน์ 2
    - math.log(math.sqrt(2 * math.pi))               #  − ½ log 2π = −0.9189 พจน์ 3
)
```

ที่มาของสามพจน์ — แค่ take log ของ E7 ตรง ๆ:

$$\mathcal{N}(a;\mu,\sigma)=\frac{1}{\sigma\sqrt{2\pi}}e^{-\frac{(a-\mu)^2}{2\sigma^2}} \;\xrightarrow{\ \log\ }\; \underbrace{-\frac{(a-\mu)^2}{2\sigma^2}}_{\text{จาก } e^{(\cdot)}} \underbrace{-\log\sigma}_{\text{จาก } 1/\sigma} \underbrace{-\tfrac12\log 2\pi}_{\text{จาก } 1/\sqrt{2\pi}}$$

**E9 · ยุบ 8 มิติ — ตรงนี้ vector กลายเป็น scalar**

$$\log\pi_\theta(a\mid s) = \sum_{i=1}^{8}\log\mathcal{N}(a_i) \qquad\Longleftrightarrow\qquad \pi_\theta(a\mid s) = \prod_{i=1}^{8}\mathcal{N}(a_i)$$

รับ `(B,8)` → คืน **`(B,)`** · [actor_critic.py:164](../tron1-rl-isaaclab/rsl_rl/rsl_rl/modules/actor_critic.py#L164)

> **หมายถึงอะไร** — รวมความชอบของ 8 ข้อเข้าเป็น "ความชอบต่อท่าทั้งท่า"
>
> **ทำไปทำไม** — เราให้เครดิตและลงโทษเป็น*ท่า* ไม่ใช่รายข้อ เพราะ reward มาจากการ
> เดินทั้งตัว ไม่ได้บอกว่าข้อไหนดีข้อไหนแย่ · การบวกในโลก log = การคูณความน่าจะเป็น
> ซึ่งถูกต้องเพราะสุ่มแต่ละข้ออิสระกัน
>
> **นี่คือที่มาของคำว่า scalar** ในตารางสัญลักษณ์ §3

8 ข้อสุ่มอิสระต่อกัน ความหนาแน่นร่วมจึงเป็นผลคูณ และ log ของผลคูณคือผลบวก —
`sum(dim=-1)` คือ $\prod$ ที่ปลอมตัวมา **มิติ 8 หายที่บรรทัดนี้ที่เดียว**

#### ช่วง D — log-prob เอาไปทำอะไรต่อ

*ประโยคเดียวของช่วงนี้: จากมาตรวัดความชอบ → ทิศและแรงที่ต้องขยับ $\theta$*

**E10 · เก็บของเก่าใส่ buffer**

$$\log\pi_{\theta_{\text{old}}}(a\mid s) \longrightarrow \texttt{storage}$$

[ppo.py:147-149](../tron1-rl-isaaclab/rsl_rl/rsl_rl/algorithm/ppo.py#L147-L149) · **แช่แข็งไว้** ไม่เปลี่ยนอีกจนจบ iteration

> **หมายถึงอะไร** — จดไว้ว่า "ตอนที่เก็บข้อมูลชุดนี้ เราชอบท่านี้เท่านี้"
>
> **ทำไปทำไม** — PPO เอาข้อมูลชุดเดียวมาใช้ซ้ำ 20 ครั้ง พอ $\theta$ ขยับไปเรื่อย ๆ ข้อมูล
> จะ "เก่า" ลง · ต้องมีหมุดปักไว้เป็นจุดอ้างอิงว่าเดินห่างจากจุดเก็บไปแค่ไหน
>
> **ถ้าไม่จด** — คำนวณ $\rho$ ไม่ได้ → clip ไม่ได้ → PPO กลายเป็น policy gradient
> ธรรมดาที่พังง่าย

**E11 · ประกอบ $\pi$ ใหม่ด้วย $\theta$ ที่ขยับแล้ว (ทำ E3–E5 ซ้ำ)**

$$\pi_{\theta_{\text{new}}}(\cdot\mid s) = \mathcal{N}\big(\mu_{\theta_{\text{new}}}(s),\ \sigma\big)$$

[ppo.py:205-210](../tron1-rl-isaaclab/rsl_rl/rsl_rl/algorithm/ppo.py#L205-L210) — บรรทัดที่คนอ่านผ่านบ่อยที่สุด:

```python
self.actor_critic.act(                       # ← เรียกแล้วไม่รับค่ากลับ!
    torch.cat((encoder_out_batch, obs_batch, commands_batch), dim=-1)
)
```

เรียก `act()` แต่ไม่เอา return value เพราะที่ต้องการคือ **side effect** — ให้
`self.distribution` ถูกสร้างใหม่ด้วย $\theta$ ปัจจุบัน action ที่มันสุ่มออกมาถูกทิ้งทันที
เพราะ PPO ต้องประเมิน $a_{\text{old}}$ ตัวเดิมเท่านั้น บรรทัดนี้คือ **ทิศ ① ที่ถูกเรียกซ้ำ
20 ครั้งต่อ iteration**

> **หมายถึงอะไร** — หลัง $\theta$ ขยับ ความเห็นของ actor เปลี่ยนไปแล้ว ต้องปั้นก้อนหมอก
> ก้อนใหม่ขึ้นมา
>
> **ทำไปทำไม** — จะถามว่า "ตอนนี้ชอบท่าเดิมแค่ไหน" ได้ ต้องมี $\pi$ ตัวใหม่ก่อน ·
> นี่คือเหตุผลที่ E3 กับ E5 ถูกเรียกซ้ำทุก gradient step ไม่ใช่แค่ตอนเก็บข้อมูล

**E12 · ประเมิน $a$ ตัวเดิม ด้วย $\pi$ ใหม่ (ทำ E8–E9 ซ้ำ)**

$$\log\pi_{\theta_{\text{new}}}(a\mid s)$$

[ppo.py:212-214](../tron1-rl-isaaclab/rsl_rl/rsl_rl/algorithm/ppo.py#L212-L214) · $a$ มาจาก buffer ไม่ได้สุ่มใหม่

> **หมายถึงอะไร** — ถามคำถามเดิม ด้วย action ชุดเดิม แต่กับ policy ใหม่
>
> **ทำไปทำไม** — เป็นการ**ควบคุมตัวแปร** · ถ้าสุ่ม action ใหม่ ตัวเลขสองตัวจะเทียบกัน
> ไม่ได้เลย เพราะเปลี่ยนสองอย่างพร้อมกัน (ทั้ง policy และ action)

**E13 · อัตราส่วน**

$$\rho = \frac{\pi_{\theta_{\text{new}}}(a\mid s)}{\pi_{\theta_{\text{old}}}(a\mid s)} = \exp\Big(\log\pi_{\theta_{\text{new}}} - \log\pi_{\theta_{\text{old}}}\Big)$$

รับ `(MB,)` สองก้อน → คืน $\rho$ `(MB,)` · [ppo.py:252-255](../tron1-rl-isaaclab/rsl_rl/rsl_rl/algorithm/ppo.py#L252-L255)

> **หมายถึงอะไร** — "ตอนนี้ชอบท่านี้มากกว่าหรือน้อยกว่าตอนเก็บข้อมูล กี่เท่า" ·
> $\rho = 1.0$ แปลว่าไม่เปลี่ยนเลย
>
> **ทำไปทำไม — สองเหตุผล** (1) เป็นไม้บรรทัดวัดว่าเดินห่างจากข้อมูลไปแค่ไหน
> (2) ในทางคณิตศาสตร์มันคือน้ำหนัก *importance sampling* ที่แก้ความเอนเอียงจากการ
> ใช้ข้อมูลที่เก็บด้วย policy เก่า
>
> **เกิน 1.2 หรือต่ำกว่า 0.8 เมื่อไร** = เดินไกลเกินกว่าที่ข้อมูลชุดนี้จะเชื่อถือได้แล้ว

**E14 · loss**

$$L^{CLIP} = \frac{1}{MB}\sum \max\Big(-\hat{A}\rho,\ -\hat{A}\cdot\text{clip}(\rho,\,0.8,\,1.2)\Big)$$

รับ `(MB,)` → คืน **scalar ตัวเดียว** · [ppo.py:256-260](../tron1-rl-isaaclab/rsl_rl/rsl_rl/algorithm/ppo.py#L256-L260)

> **หมายถึงอะไร** — แปลง "ท่านี้ดีแค่ไหน ($\hat{A}$)" + "ขยับไปเท่าไร ($\rho$)" เป็นคะแนน
> ที่ต้องทำให้ต่ำที่สุด
>
> **ทำไมมีเครื่องหมายลบ** — optimizer ทำได้อย่างเดียวคือ "ทำ loss ให้เล็กลง" ·
> ถ้าอยากได้ $\hat{A}$ สูง ต้องเขียนเป็น $-\hat{A}$
>
> **ทำไม $\max$ ของสองค่าที่เป็นลบ** — คือการเลือกอันที่ *ให้รางวัลน้อยกว่า* = มองโลก
> ในแง่ร้ายไว้ก่อน · นี่คือหัวใจของคำว่า **Proximal**: ถ้าขยับเกินขอบไปแล้ว จะไม่ได้รางวัล
> เพิ่มอีก **gradient กลายเป็น 0 พอดี** (โน้ต 07 §5.3)

**E15 · gradient ย้อนกลับถึง $\mu$**

$$\frac{\partial L}{\partial \mu_i} = -\hat{A}\,\rho\,\frac{a_i - \mu_i}{\sigma_i^2} \qquad (\text{กรณีไม่โดน clip})$$

จากนั้น chain rule ต่อเข้าไปใน NN ถึง $\theta$ ทุกตัว · `loss.backward()` + `optimizer.step()`

> **หมายถึงอะไร** — "ต้องขยับ $\mu$ ไปทางไหน และแรงแค่ไหน"
>
> **อ่านทีละส่วน**
>
> | ส่วน | ความหมาย |
> | --- | --- |
> | $(a_i - \mu_i)$ | **ทิศ** — ชี้จากค่ากลางไปหาท่าที่ลองมา |
> | $\hat{A}$ | **ดีหรือแย่ และแค่ไหน** — บวก = เข้าหา · ลบ = หนี |
> | $1/\sigma_i^2$ | **ยิ่งกล้าลองน้อย ยิ่งขยับแรง** — $\sigma$ เล็ก แปลว่าการเบี่ยงจากค่ากลางนิดเดียวก็เป็นข้อมูลหนักแน่น |
> | $\rho$ | **ถ่วงน้ำหนักความเกี่ยวข้อง** ของข้อมูลชุดนี้กับ policy ปัจจุบัน |
>
> **ทั้งอัลกอริทึมจบที่บรรทัดนี้** — ทุกสมการก่อนหน้ามีไว้เพื่อคำนวณ "ทิศและแรง" นี้ให้ถูก

จึงไม่โดน clip

$$L^{CLIP} = \max(-1.2048,\ -1.2048) = \mathbf{-1.2048}$$

**E15 · gradient กลับถึง $\mu$ แต่ละตัว**

$$\frac{\partial L}{\partial \mu_i} = -1.10 \times 1.0953 \times \frac{a_i - \mu_i^{\text{new}}}{0.25}$$

| $i$ | $a_i - \mu_i^{\text{new}}$ | $\partial L/\partial\mu_i$ | Adam จะ… |
| --- | --- | --- | --- |
| 1 | $+0.160$ | $-0.7711$ | **เพิ่ม** $\mu_1$ |
| 2 | $-0.040$ | $+0.1928$ | ลด $\mu_2$ |
| 3 | $+0.445$ | $-2.1445$ | **เพิ่มแรง** $\mu_3$ |
| 4 | $-0.275$ | $+1.3253$ | ลด $\mu_4$ |
| 5 | $+0.025$ | $-0.1205$ | เพิ่มนิดเดียว |
| 6 | $+0.595$ | $-2.8674$ | **เพิ่มแรงสุด** $\mu_6$ |
| 7 | $-0.300$ | $+1.4458$ | ลด $\mu_7$ |
| 8 | $+0.060$ | $-0.2892$ | เพิ่ม $\mu_8$ |

**อ่านตารางนี้ให้ออกคือเข้าใจ PPO ทั้งหมด** — เพราะ $\hat{A} = +1.10 > 0$ แปลว่า *"ครั้งนั้น
ทำได้ดีกว่าที่ critic คาด"* gradient จึงลาก $\mu$ **เข้าหา $a$ ที่สุ่มไป** ทุกมิติ (เครื่องหมายของ
$\partial L/\partial\mu_i$ ตรงข้ามกับ $a_i - \mu_i$ เสมอ) และมิติที่สุ่มไปไกลที่สุด (มิติ 6) ถูกลากแรงที่สุด
ถ้า $\hat{A}$ เป็นลบ เครื่องหมายทั้งคอลัมน์จะกลับหมด → **ผลัก $\mu$ หนีจาก $a$**

### 3.5.7 สคริปต์ตรวจด้วยตัวเอง

รันได้เลย ไม่ต้องมี torch — ตัวเลขทุกตัวใน §3.5.5 ออกมาจากสคริปต์นี้:

```python
import math

MU    = [0.42, -0.31, 0.05, 0.88, -0.12, 0.20, -0.55, 0.33]
EPS   = [0.38, -0.12, 0.91, -0.47, 0.05, 1.23, -0.66, 0.14]
SIGMA = 0.5
A_HAT = 1.10
C     = math.log(math.sqrt(2 * math.pi))          # 0.9189 — พจน์ที่ 3 ของ E8

def pdf(x, mu, sigma):                            # E7
    return math.exp(-((x - mu) ** 2) / (2 * sigma ** 2)) / (sigma * math.sqrt(2 * math.pi))

def log_pdf(x, mu, sigma):                        # E8 — ตรงกับ normal.py:88-92
    return -((x - mu) ** 2) / (2 * sigma ** 2) - math.log(sigma) - C

a       = [m + SIGMA * e for m, e in zip(MU, EPS)]            # E6
log_old = sum(log_pdf(ai, mi, SIGMA) for ai, mi in zip(a, MU))  # E9  → -3.3955

MU_NEW  = [0.45, -0.33, 0.06, 0.92, -0.12, 0.22, -0.58, 0.34]
log_new = sum(log_pdf(ai, mi, SIGMA) for ai, mi in zip(a, MU_NEW))  # E12 → -3.3045

rho  = math.exp(log_new - log_old)                            # E13 → 1.0953
loss = max(-A_HAT * rho, -A_HAT * min(max(rho, 0.8), 1.2))    # E14 → -1.2048
grad = [-A_HAT * rho * (ai - mi) / SIGMA ** 2                 # E15
        for ai, mi in zip(a, MU_NEW)]

print(f"a        = {[round(x, 3) for x in a]}")
print(f"log_old  = {log_old:.4f}   pi = {math.exp(log_old):.5f}")
print(f"log_new  = {log_new:.4f}")
print(f"rho      = {rho:.4f}")
print(f"L_CLIP   = {loss:.4f}")
print(f"dL/dmu   = {[round(g, 4) for g in grad]}")
```

เปลี่ยน `A_HAT` เป็นค่าลบแล้วรันใหม่ — เครื่องหมายของ `dL/dmu` จะกลับทั้งแถว
นั่นคือกลไก "ผลัก $\mu$ หนีจาก action ที่แย่" · เปลี่ยน `SIGMA` เป็น `0.25` แล้วขยับ
`MU_NEW` ให้ห่างขึ้น จะเห็น `rho` ทะลุ 1.2 แล้ว clip เริ่มทำงาน (โน้ต 07 §5.3)
