## 0. ห้าหน่วยนับคือห้าวิธีหั่นตารางเดียวกัน

ก่อนจะคำนวณอะไร ต้องเห็นภาพนี้ให้ชัดก่อน — **ข้อมูลของหนึ่ง iteration คือตาราง
สองมิติ** แถว = step (24) คอลัมน์ = environment (2048) แต่ละช่อง = หนึ่ง
transition $(s, a, r, V, \log\pi, \text{done})$

```text
                    env 0   env 1   env 2   ...   env 2047        ← 2048 คอลัมน์
                  ┌───────┬───────┬───────┬─────┬───────┐
   step t = 0     │  ▪    │  ▪    │  ▪    │ ... │  ▪    │  ┐
   step t = 1     │  ▪    │  ▪    │  ▪    │ ... │  ▪    │  │
   step t = 2     │  ▪    │  ▪    │  ▪    │ ... │  ▪    │  │  24 แถว
        ⋮         │  ⋮    │  ⋮    │  ⋮    │     │  ⋮    │  │
   step t = 23    │  ▪    │  ▪    │  ▪    │ ... │  ▪    │  ┘
                  └───────┴───────┴───────┴─────┴───────┘
                                                           = 49,152 ช่อง

   ▪ = 1 step         = 1 ช่อง
   episode            = ช่วงต่อเนื่องในแนวตั้งของ 1 คอลัมน์ จนถึงช่องที่ done=1
                        (อาจสั้นกว่า 24 หรือยาวข้ามหลายตาราง)
   iteration          = ตารางทั้งใบ  → GAE ครั้งเดียว → เรียนรู้ → ล้าง → ตารางใหม่
   epoch              = การเดินผ่านทุกช่องในตารางครบ 1 รอบ
   mini-batch         = ช่องที่สุ่มมา 1/4 ของตาราง (12,288 ช่อง) → 1 gradient step
```

| หน่วย | คืออะไรในตาราง | คำนวณอะไร "ที่ระดับนี้" | ใน toy | ใน Tron1 |
| --- | --- | --- | --- | --- |
| **step** | 1 ช่อง | forward pass: $\mu, a, \log\pi, V$ · env: $r$, done | 8 ช่อง | 49,152 ช่อง |
| **episode** | ช่วงแนวตั้งใน 1 คอลัมน์ | **ไม่มีสูตร** — แค่ reset env และจดความยาว · แต่ `done` ตัดสาย GAE | e1 มี 2 episode | ~1000 steps ≈ 42 ตาราง |
| **iteration** | ตารางทั้งใบ | GAE + normalize **ครั้งเดียว** ทุกช่องพร้อมกัน แล้ว epoch × minibatch gradient steps แล้ว KL → lr | 1 ตาราง 2×4 | 1 ตาราง 24×2048 |
| **epoch** | เดินครบทุกช่อง | สับลำดับช่อง → หั่นเป็น minibatch | 2 epoch × 2 mb | 5 epoch × 4 mb |
| **mini-batch** | ช่องสุ่ม 1/M ของตาราง | $\rho, L^{CLIP}, L_V, H$ → **1 gradient step** | 4 ช่อง | 12,288 ช่อง |

**สองสิ่งที่คนมักเข้าใจผิด:**

1. **episode ไม่ใช่หน่วยของอัลกอริทึม** — PPO ไม่เคยรอ episode จบ ไม่เคยคำนวณ
   อะไร "ต่อ episode" มันเป็นหน่วยของ*environment* (เมื่อไหร่ต้อง reset) และของ
   *การวัดผล* (`Mean episode length`) เท่านั้น สิ่งเดียวที่ episode มีผลต่อคณิตศาสตร์
   คือ `done` ที่ตัดสาย bootstrap ใน GAE (§4.2)
2. **gradient step เกิดที่ระดับ mini-batch ไม่ใช่ iteration** — 1 iteration มี
   5 × 4 = 20 gradient steps; GAE ต่างหากที่เกิดครั้งเดียวต่อ iteration

## 2. ระดับ STEP — สิ่งที่คำนวณต่อหนึ่งช่อง

ทุกช่องทำสี่อย่างนี้ **พร้อมกันทั้ง $B$ คอลัมน์** (tensor operation ครั้งเดียว):

### 2.1 สุ่ม action — สมการ (8) ของโน้ต 05

$$a = \mu + \sigma\,\varepsilon$$

| ช่อง | $\mu$ | $\sigma\varepsilon$ | $a$ |
| --- | --- | --- | --- |
| e0 t0 | 0.20 | 0.5 × (+0.40) = +0.20 | **+0.40** |
| e0 t1 | 0.30 | 0.5 × (−0.20) = −0.10 | **+0.20** |
| e0 t2 | 0.10 | 0.5 × (+0.80) = +0.40 | **+0.50** |
| e0 t3 | 0.40 | 0.5 × (0.00) = 0.00 | **+0.40** |
| e1 t0 | −0.10 | 0.5 × (−0.60) = −0.30 | **−0.40** |
| e1 t1 | 0.00 | 0.5 × (+0.80) = +0.40 | **+0.40** |
| e1 t2 | 0.20 | 0.5 × (+0.20) = +0.10 | **+0.30** |
| e1 t3 | −0.30 | 0.5 × (+0.40) = +0.20 | **−0.10** |

### 2.2 $\log\pi_{old}(a \mid s)$ — derive จาก Gaussian PDF

เริ่มจากสมการ (7): $p(a) = \dfrac{1}{\sigma\sqrt{2\pi}} \exp\!\left(-\dfrac{(a-\mu)^2}{2\sigma^2}\right)$

ใส่ $\log$ ทั้งสองข้าง แล้วใช้กฎ $\log(xy) = \log x + \log y$ และ $\log e^u = u$:

| ขั้น | ผล |
| --- | --- |
| $\log p = \log\!\big(\tfrac{1}{\sigma\sqrt{2\pi}}\big) + \log\exp(\cdots)$ | แยกผลคูณเป็นผลบวก |
| $= -\log\sigma - \log\sqrt{2\pi} - \dfrac{(a-\mu)^2}{2\sigma^2}$ | $\log\tfrac{1}{x} = -\log x$ และ $\log\sqrt{2\pi} = \tfrac12\log 2\pi$ |

$$\boxed{\;\log\pi(a\mid s) = -\tfrac{1}{2}\ln 2\pi \;-\; \ln\sigma \;-\; \frac{(a-\mu)^2}{2\sigma^2}\;} \tag{7'}$$

สองพจน์แรก**คงที่ทั้งตาราง** (เพราะ $\sigma$ ไม่ขึ้นกับ state): $-\tfrac12\ln 2\pi = -0.9189$
และ $-\ln 0.5 = +0.6931$ รวม $= -0.2258$ เหลือแค่พจน์สุดท้ายที่ต่างกันต่อช่อง:

| ช่อง | $(a-\mu)$ | $(a-\mu)^2 / (2\sigma^2)$ = $(a-\mu)^2/0.5$ | $\log\pi_{old}$ = −0.2258 − พจน์นั้น |
| --- | --- | --- | --- |
| e0 t0 | 0.20 | 0.0800 | **−0.3058** |
| e0 t1 | −0.10 | 0.0200 | **−0.2458** |
| e0 t2 | 0.40 | 0.3200 | **−0.5458** |
| e0 t3 | 0.00 | 0.0000 | **−0.2258** |
| e1 t0 | −0.30 | 0.1800 | **−0.4058** |
| e1 t1 | 0.40 | 0.3200 | **−0.5458** |
| e1 t2 | 0.10 | 0.0200 | **−0.2458** |
| e1 t3 | 0.20 | 0.0800 | **−0.3058** |

> **สังเกต:** e0 t3 ที่ $\varepsilon = 0$ (สุ่มได้ตรง $\mu$ พอดี) มี $\log\pi$ สูงสุด =
> −0.2258 = ค่าที่ยอดระฆัง ยิ่ง $a$ ห่างจาก $\mu$ ยิ่งติดลบมาก — ตรงกับตารางลดทอน
> ในโน้ต 05 หัวข้อ 2.3 · ค่านี้ถูก**เก็บลง buffer** เพื่อใช้เป็น "ค่าอ้างอิงจากอดีต"
> ตอนคำนวณ $\rho$ ใน §5 — ในโค้ดคือ [ppo.py:147](../tron1-rl-isaaclab/rsl_rl/rsl_rl/algorithm/ppo.py#L147)

### 2.3 $V(s)$ และ $r$, done

$V$ มาจาก critic forward pass (สมการ (5) ซ้อน 4 ชั้น) — ในตัวอย่างนี้ให้มาแล้ว ·
$r$ กับ done มาจาก `env.step()` หลังส่ง $a \times 0.25$ เข้า PD (โน้ต 05 หัวข้อ 2.5)

**สรุประดับ step:** หนึ่งช่องเก็บ 6 ค่า $(s,\ a,\ r,\ V,\ \log\pi_{old},\ \text{done})$
ทำ 4 ครั้ง (t=0..3) × 2 คอลัมน์ = 8 ช่องเต็ม → จบช่วง A

## 3. ระดับ EPISODE — ไม่มีสูตร แต่มีผลข้างเคียงหนึ่งอย่าง

env 1 มี 2 episode ในตารางนี้: $\{t_0, t_1, t_2\}$ (จบเพราะล้ม) และ $\{t_3, \ldots\}$
(ต่อไปยังตารางถัดไป) · env 0 มี episode เดียวที่ยังไม่จบ (ต่อไปตารางหน้า)

สิ่งที่ episode "ทำ":

| อะไร | ทำโดยใคร | สูตรไหม |
| --- | --- | --- |
| reset env กลับท่าเริ่มต้น | environment | ไม่ |
| จดความยาว → `Mean episode length` | logger | ไม่ (แค่นับ) |
| จดผลรวม reward → `Mean reward` | logger | ไม่ (แค่บวก) |
| **ตั้ง done=1 ที่ช่องสุดท้าย** | environment | **มีผลต่อ GAE ใน §4.2** |

นั่นคือทั้งหมด — **ไม่มีสมการไหนในโน้ต 05 ที่คำนวณ "ต่อ episode"** สมการ (1) และ
(2) พูดถึงผลรวมถึง $T$ ก็จริง แต่ในทางปฏิบัติถูกแทนด้วย bootstrap (§4.1) ทำให้

## 4. ระดับ ITERATION (ส่วนที่ทำครั้งเดียว) — GAE ทั้งตาราง

ตอนนี้ตารางเต็มแล้ว ก่อนจะเรียนรู้ ต้องแปลง $(r, V)$ ทุกช่องให้เป็น "เครดิต" $A$
ทำ**ครั้งเดียว** ทุกคอลัมน์พร้อมกัน ไล่จากแถวล่างขึ้นบน

### 4.1 Bootstrap — ค่าที่ "ขอบตาราง"

แถวสุดท้าย (t=3) ไม่มีแถว t=4 ให้ดู $V$ ถัดไป → ให้ critic ทำนาย $V(s_4)$ จาก state
หลังสุด: $V_{last} = 3.0$ (e0), $3.5$ (e1) — นี่คือ **bootstrapping** ตามโน้ต 05
หัวข้อ 3.2: ใช้ค่าประมาณแทนการรอผลจริง

### 4.2 TD-error $\delta_t$ — derive จากสมการ Bellman

สมการ (3): $V(s_t) = \mathbb{E}[r_t + \gamma V(s_{t+1})]$ บอกว่า *ถ้า critic แม่น*
ข้างซ้ายเท่าข้างขวา · **ส่วนต่าง**ระหว่างสองข้างจึงวัดว่า critic เดาพลาดเท่าไหร่:

$$\boxed{\;\delta_t = r_t + \underbrace{(1-\text{done}_t)}_{\text{mask}}\,\gamma\, V(s_{t+1}) - V(s_t)\;} \tag{10'}$$

พจน์ $(1-\text{done}_t)$ คือสิ่งที่โค้ดเรียก `next_is_not_terminal` — ถ้า episode จบ
ที่ช่องนี้ **ไม่มี** $s_{t+1}$ ที่มีความหมาย (env reset ไปแล้ว) จึงต้องตัดพจน์ bootstrap
ทิ้ง ไล่จาก t=3 ลงมา:

| ช่อง | $r_t$ | mask | $\gamma\cdot V_{t+1}$ | $V_t$ | $\delta_t$ |
| --- | --- | --- | --- | --- | --- |
| e0 t3 | 0.5 | 1 | 0.9 × 3.0 (=$V_{last}$) = 2.70 | 3.5 | 0.5 + 2.70 − 3.5 = **−0.30** |
| e0 t2 | 1.0 | 1 | 0.9 × 3.5 = 3.15 | 4.0 | **+0.15** |
| e0 t1 | 0.5 | 1 | 0.9 × 4.0 = 3.60 | 4.5 | **−0.40** |
| e0 t0 | 1.0 | 1 | 0.9 × 4.5 = 4.05 | 5.0 | **+0.05** |
| e1 t3 | 0.0 | 1 | 0.9 × 3.5 (=$V_{last}$) = 3.15 | 4.0 | **−0.85** |
| e1 t2 | −2.0 | **0** | **0** × 0.9 × 4.0 = 0 | 1.0 | −2.0 + 0 − 1.0 = **−3.00** |
| e1 t1 | 1.0 | 1 | 0.9 × 1.0 = 0.90 | 2.0 | **−0.10** |
| e1 t0 | 0.5 | 1 | 0.9 × 2.0 = 1.80 | 3.0 | **−0.70** |

> **ดูแถว e1 t2:** ถ้าไม่มี mask จะได้ $\delta = -2 + 3.6 - 1 = +0.6$ — บอกว่า "ล้ม
> แล้วดีกว่าที่คาด" ซึ่งผิดสิ้นเชิง เพราะ 3.6 นั้นคือ $V$ ของ*ท่ายืนใหม่หลัง reset*
> ไม่ใช่อนาคตของท่าที่กำลังล้ม mask ทำให้ได้ −3.0 ที่ถูกต้อง: ล้มคือแย่มาก

### 4.3 Advantage $A_t$ — derive ว่า recursion กับ closed-form คือสิ่งเดียวกัน

โน้ต 05 สมการ (11) เขียน GAE เป็นผลรวม: $A_t = \sum_{k\ge0}(\gamma\lambda)^k\delta_{t+k}$
แต่โค้ดเขียนเป็น **recursion**:

$$\boxed{\;A_t = \delta_t + (1-\text{done}_t)\,\gamma\lambda\, A_{t+1}, \qquad A_{T} = 0\;} \tag{11'}$$

**พิสูจน์ว่าเท่ากัน** (ไม่มี done): แทน $A_{t+1}$ ด้วยนิยามของมันเองซ้ำ ๆ

| ขั้น | ผล |
| --- | --- |
| $A_t = \delta_t + \gamma\lambda A_{t+1}$ | นิยาม |
| $= \delta_t + \gamma\lambda(\delta_{t+1} + \gamma\lambda A_{t+2})$ | แทน $A_{t+1}$ |
| $= \delta_t + \gamma\lambda\,\delta_{t+1} + (\gamma\lambda)^2 A_{t+2}$ | กระจาย |
| $= \delta_t + \gamma\lambda\,\delta_{t+1} + (\gamma\lambda)^2\delta_{t+2} + (\gamma\lambda)^3 A_{t+3}$ | แทนอีกครั้ง |
| $= \sum_{k=0}^{T-1-t}(\gamma\lambda)^k\delta_{t+k}$ | ทำจนถึง $A_T = 0$ ∎ |

recursion จึงเป็นแค่วิธี*คำนวณ*ผลรวมนั้นให้เร็ว (คูณบวกทีละก้าวแทนที่จะยกกำลังใหม่
ทุกครั้ง) และ mask $(1-\text{done})$ ทำให้ผลรวม**หยุด**ที่ขอบ episode

**คำนวณด้วย recursion** ($\gamma\lambda = 0.72$, เริ่ม $A_4 = 0$):

| ช่อง | $\delta_t$ | mask × 0.72 × $A_{t+1}$ | $A_t$ |
| --- | --- | --- | --- |
| e0 t3 | −0.30 | 1 × 0.72 × 0 = 0 | **−0.3000** |
| e0 t2 | +0.15 | 1 × 0.72 × (−0.30) = −0.2160 | **−0.0660** |
| e0 t1 | −0.40 | 1 × 0.72 × (−0.066) = −0.0475 | **−0.4475** |
| e0 t0 | +0.05 | 1 × 0.72 × (−0.4475) = −0.3222 | **−0.2722** |
| e1 t3 | −0.85 | 1 × 0.72 × 0 = 0 | **−0.8500** |
| e1 t2 | −3.00 | **0** × 0.72 × (−0.85) = 0 | **−3.0000** |
| e1 t1 | −0.10 | 1 × 0.72 × (−3.0) = −2.1600 | **−2.2600** |
| e1 t0 | −0.70 | 1 × 0.72 × (−2.26) = −1.6272 | **−2.3272** |

**ตรวจด้วย closed-form** (ทำเองบนกระดาษได้):

$$A_0^{(e0)} = \delta_0 + 0.72\,\delta_1 + 0.72^2\,\delta_2 + 0.72^3\,\delta_3
= 0.05 - 0.288 + 0.0778 - 0.1120 = \mathbf{-0.2722}\ \checkmark$$

$$A_0^{(e1)} = \delta_0 + 0.72\,\delta_1 + 0.72^2\,\delta_2 + \underbrace{0\cdot\delta_3}_{\text{mask ตัด}}
= -0.70 - 0.072 - 1.5552 = \mathbf{-2.3272}\ \checkmark$$

> สังเกต e1: $\delta_3 = -0.85$ **ไม่ถูกนับ**ใน $A_0$ เพราะเป็นคนละ episode — ถ้าไม่มี
> mask จะเอาความล้มเหลวของ episode หน้าไปโทษ action ใน episode ก่อน

นี่คือ "คำตอบเฉลย" ที่จะเอาไปสอน critic ใน §5.4

### 4.5 Normalize advantage — ทำครั้งเดียวทั้งตาราง

$$\hat A = \frac{A - \text{mean}(A)}{\text{std}(A) + 10^{-8}}$$

ทำไม: ทำให้ขนาดของ $A$ อยู่ราว ๆ $\pm 1$ เสมอไม่ว่า reward จะใหญ่หรือเล็ก → learning
rate ตัวเดียวใช้ได้ทุกงาน · คำนวณจาก**ทั้ง 8 ค่า**พร้อมกัน (ทั้ง 49,152 ใน Tron1):

$$\text{mean} = \frac{-0.2722-0.4475-0.0660-0.3000-2.3272-2.2600-3.0000-0.8500}{8} = -1.1904$$

$$\text{std} = \sqrt{\frac{\sum (A_i - \text{mean})^2}{8-1}} = 1.1513$$

> **กับดัก:** `torch.std()` หารด้วย $n-1$ (unbiased) ไม่ใช่ $n$ — ถ้าคุณคำนวณด้วยมือ
> แล้วได้ 1.077 แปลว่าหารด้วย 8 ต้องหารด้วย 7 ถึงจะตรงกับโค้ด

| ช่อง | $A$ | $\hat A = (A + 1.1904)/1.1513$ |
| --- | --- | --- |
| e0 t0 | −0.2722 | **+0.7975** |
| e0 t1 | −0.4475 | **+0.6452** |
| e0 t2 | −0.0660 | **+0.9766** |
| e0 t3 | −0.3000 | **+0.7733** |
| e1 t0 | −2.3272 | **−0.9874** |
| e1 t1 | −2.2600 | **−0.9290** |
| e1 t2 | −3.0000 | **−1.5718** |
| e1 t3 | −0.8500 | **+0.2956** |

**อ่านผล:** ทุก action ของ e0 กลายเป็น "ดีกว่าค่าเฉลี่ย" (บวก) และ e1 t0–t2 เป็น
"แย่กว่า" (ลบ) — แม้ $A$ ดิบของ e0 จะติดลบทั้งหมด! เพราะ normalize วัด**เทียบกับ
เพื่อนในตารางเดียวกัน** ไม่ใช่เทียบกับศูนย์ นี่คือเหตุผลที่โน้ต 05 หัวข้อ 4.4 เตือนว่า
PPO ไม่ได้ดู reward ดิบ

## 5. ระดับ EPOCH และ MINI-BATCH — ที่ที่ weight เปลี่ยน

### 5.1 หั่นตาราง

8 ช่อง → สับลำดับ → หั่นเป็น 2 minibatch ละ 4 ช่อง · เดินครบทั้ง 2 = 1 epoch ·
ทำ 2 epoch (สับใหม่ทุก epoch) = **4 gradient steps ต่อ iteration**

```text
epoch 1:  สับ → mb₀ = {e0t0, e0t2, e1t1, e1t3}   → gradient step #1
                mb₁ = {e0t1, e0t3, e1t0, e1t2}   → gradient step #2
epoch 2:  สับใหม่ → mb₀' = {…4 ช่อง…}            → gradient step #3
                    mb₁' = {…4 ช่อง…}            → gradient step #4
                                                   (Tron1: 5 × 4 = 20 steps)
```

**จุดสำคัญ:** ข้อมูล $(a, \log\pi_{old}, \hat A, R)$ ในตาราง**ไม่เปลี่ยน**ตลอด 4 steps
สิ่งที่เปลี่ยนคือ $\theta$ → $\mu_{new}$ → $\log\pi_{new}$ → $\rho$ ที่คำนวณใหม่ทุก step

### 5.2 หนึ่ง gradient step บน mb₀ — ไล่ทุกสูตร

สมมติหลัง gradient step ก่อนหน้า actor คาย $\mu$ ที่**ต่างจากตอนเก็บข้อมูล**
เล็กน้อย: $\mu_{new} = \mu_{old} + 0.05$ ทุกช่อง (ในความจริง network คำนวณค่านี้ใหม่
จาก $s$ เดิม แต่ด้วย weight ใหม่)

**(ก) $\rho$ — derive จากนิยาม**

$$\rho = \frac{\pi_{new}(a\mid s)}{\pi_{old}(a\mid s)}
= \frac{e^{\log\pi_{new}}}{e^{\log\pi_{old}}}
= e^{\log\pi_{new} - \log\pi_{old}}$$

จึงไม่ต้องคำนวณ $\pi$ ตรง ๆ แค่**ลบ log สองตัวแล้ว exp** — เสถียรกว่ามาก ·
$\log\pi_{new}$ ใช้สูตร (7') เดิมแต่แทน $\mu_{new}$ และ $a$ *ตัวเดิม*จาก buffer:

| ช่อง | $a$ | $\mu_{new}$ | $(a-\mu_{new})^2/0.5$ | $\log\pi_{new}$ | $\log\pi_{old}$ | $\Delta$ | $\rho = e^\Delta$ |
| --- | --- | --- | --- | --- | --- | --- | --- |
| e0 t0 | 0.40 | 0.25 | 0.0450 | −0.2708 | −0.3058 | +0.0350 | **1.0356** |
| e0 t2 | 0.50 | 0.15 | 0.2450 | −0.4708 | −0.5458 | +0.0750 | **1.0779** |
| e1 t1 | 0.40 | 0.05 | 0.2450 | −0.4708 | −0.5458 | +0.0750 | **1.0779** |
| e1 t3 | −0.10 | −0.25 | 0.0450 | −0.2708 | −0.3058 | +0.0350 | **1.0356** |

ทุก $\rho > 1$ เพราะ $\mu$ ขยับ*เข้าหา* $a$ ในทุกช่อง (บังเอิญจากที่เลือก +0.05) →
policy ใหม่ "ชอบ" action เก่าเหล่านี้มากขึ้น 3–8%

**(ข) Clipped surrogate — สมการ (12)**

$$L_i = \max\big(-\rho_i\hat A_i,\; -\text{clip}(\rho_i, 0.8, 1.2)\,\hat A_i\big)$$

(เขียนเป็น loss ที่ต้อง*ลด* จึงติดลบจากสมการ (12) และ $\min$ กลายเป็น $\max$ —
ตรงกับ [ppo.py:256-260](../tron1-rl-isaaclab/rsl_rl/rsl_rl/algorithm/ppo.py#L256-L260))

| ช่อง | $\rho$ | clip$(\rho)$ | $\hat A$ | $-\rho\hat A$ | $-\text{clip}(\rho)\hat A$ | $L_i = \max$ | clip ทำงาน? |
| --- | --- | --- | --- | --- | --- | --- | --- |
| e0 t0 | 1.0356 | 1.0356 | +0.7975 | −0.8259 | −0.8259 | **−0.8259** | ไม่ (ρ ในช่วง) |
| e0 t2 | 1.0779 | 1.0779 | +0.9766 | −1.0526 | −1.0526 | **−1.0526** | ไม่ |
| e1 t1 | 1.0779 | 1.0779 | −0.9290 | +1.0014 | +1.0014 | **+1.0014** | ไม่ |
| e1 t3 | 1.0356 | 1.0356 | +0.2956 | −0.3062 | −0.3062 | **−0.3062** | ไม่ |

$$L^{CLIP} = \text{mean}(L_i) = \frac{-0.8259 - 1.0526 + 1.0014 - 0.3062}{4} = \mathbf{-0.2958}$$

**อ่าน:** e1 t1 ให้ loss *บวก* (แย่) เพราะ $\hat A < 0$ (action นั้นแย่) แต่ $\rho > 1$
(policy ใหม่ดันชอบมัน*มากขึ้น*) — gradient จะแก้ตรงนี้ · ยังไม่มี clip เพราะ $\rho$
ทุกตัวอยู่ใน $[0.8, 1.2]$ — ดู §5.3 ว่าเมื่อไหร่มันจะทำงาน

**(ค) Gradient $\partial L/\partial\mu$ — derive ด้วยมือ: หัวใจของ "ทำไม policy ถึงเรียนรู้"**

เมื่อ $\rho$ อยู่ในช่วง clip พจน์ที่ใช้คือ $-\rho\hat A$ · หาอนุพันธ์เทียบ $\mu_{new}$
(ค่าที่ actor คาย) ผ่าน chain rule:

| ขั้น | ผล | เหตุผล |
| --- | --- | --- |
| $\dfrac{\partial \log\pi}{\partial\mu} = \dfrac{\partial}{\partial\mu}\Big[-\dfrac{(a-\mu)^2}{2\sigma^2}\Big] = \dfrac{a-\mu}{\sigma^2}$ | จาก (7') พจน์เดียวที่มี $\mu$ · อนุพันธ์ของ $-(a-\mu)^2$ คือ $+2(a-\mu)$ |
| $\dfrac{\partial\rho}{\partial\mu} = \rho\cdot\dfrac{\partial\log\pi}{\partial\mu} = \rho\,\dfrac{a-\mu}{\sigma^2}$ | เพราะ $\rho = e^{\log\pi_{new} - c}$ และ $\frac{d}{dx}e^{f} = e^{f}f'$ |
| $\dfrac{\partial L}{\partial\mu} = -\hat A\,\dfrac{\partial\rho}{\partial\mu}$ | $\hat A$ เป็นค่าคงที่ (มาจาก buffer) |

$$\boxed{\;\frac{\partial L}{\partial\mu} = -\hat A\;\rho\;\frac{a-\mu_{new}}{\sigma^2}\;} \tag{G}$$

**อ่านสมการ (G) ให้ได้ความหมาย** — gradient descent ทำ $\mu \leftarrow \mu - \alpha\,\partial L/\partial\mu$:

| กรณี | $\hat A$ | $a - \mu$ | $\partial L/\partial\mu$ | $\mu$ เคลื่อนไป | แปลว่า |
| --- | --- | --- | --- | --- | --- |
| action ดี, $a$ อยู่ขวาของ $\mu$ | + | + | **−** | **ขวา** (เข้าหา $a$) | "ทำแบบนั้นอีก" |
| action ดี, $a$ อยู่ซ้ายของ $\mu$ | + | − | + | ซ้าย (เข้าหา $a$) | "ทำแบบนั้นอีก" |
| action แย่, $a$ อยู่ขวาของ $\mu$ | − | + | + | ซ้าย (**หนี** $a$) | "อย่าทำแบบนั้น" |
| action แย่, $a$ อยู่ซ้ายของ $\mu$ | − | − | − | ขวา (หนี $a$) | "อย่าทำแบบนั้น" |

**นี่คือ policy gradient ทั้งหมดในหนึ่งบรรทัด:** ขยับ $\mu$ เข้าหา action ที่ได้ advantage
บวก หนีจาก action ที่ได้ advantage ลบ โดยแรงเป็นสัดส่วนกับ $|\hat A|$

ตัวเลขจริง ($\sigma^2 = 0.25$):

| ช่อง | $\hat A$ | $\rho$ | $a - \mu_{new}$ | $\partial L/\partial\mu = -\hat A\rho(a-\mu)/0.25$ | SGD $\alpha=0.1$: $\mu \leftarrow \mu - 0.1\,\partial L/\partial\mu$ |
| --- | --- | --- | --- | --- | --- |
| e0 t0 | +0.7975 | 1.0356 | +0.15 | **−0.4955** | 0.25 → **0.2995** (เข้าหา a=0.40 ✓) |
| e0 t2 | +0.9766 | 1.0779 | +0.35 | **−1.4737** | 0.15 → **0.2974** (เข้าหา a=0.50 ✓) |
| e1 t1 | −0.9290 | 1.0779 | +0.35 | **+1.4020** | 0.05 → **−0.0902** (หนีจาก a=0.40 ✓) |
| e1 t3 | +0.2956 | 1.0356 | +0.15 | **−0.1837** | −0.25 → **−0.2316** (เข้าหา a=−0.10 ✓) |

> **จาก $\mu$ ไปถึง $\theta$:** ในเครือข่ายจริง $\mu$ ไม่ใช่ตัวแปรอิสระ — มันคือ output
> ของ MLP ดังนั้น $\partial L/\partial\theta = \partial L/\partial\mu \cdot \partial\mu/\partial\theta$
> พจน์หลังคือ backpropagation ผ่าน 4 ชั้น (โน้ต 05 หัวข้อ 2.2) ที่ PyTorch ทำให้ใน
> `loss.backward()` — สิ่งที่ derive ด้วยมือได้และ*ควร*เข้าใจคือพจน์แรก (G) เพราะมันคือ
> ส่วนที่บอกว่า "เรียนรู้ไปทางไหน" · Adam ต่างจาก SGD ตรงที่ปรับขนาดก้าวต่อ weight
> อัตโนมัติ แต่**ทิศทาง**เดียวกัน

### 5.3 เมื่อไหร่ clip จะทำงาน — คำนวณจากคู่แฝดในตาราง

ในตัวอย่างข้างบน clip ไม่ทำงานเลยเพราะ $\mu$ ขยับแค่ 0.05 · ตารางนี้จงใจมี **คู่แฝด**
ไว้ให้ทดสอบ: **e0 t2** กับ **e1 t1** มี $|a-\mu| = 0.40$ เท่ากัน จึงมี $\log\pi_{old} = -0.5458$
เท่ากัน และเมื่อ $\mu$ ขยับเท่ากันก็ได้ $\rho$ เท่ากันเป๊ะ — **ต่างกันแค่เครื่องหมายของ $\hat A$**
($+0.9766$ กับ $-0.9290$) · เท่านี้ก็เห็น clip ครบทั้งสี่กรณีจากตัวเลขในตารางเดียวกัน

**กฎการขยับ:** สมมติว่าผ่านไปหลาย gradient step แล้ว $\mu$ เดินตามทิศที่สมการ (G) สั่ง
จนสะสมได้ $\mu_{new} = \mu_{old} + \operatorname{sign}(\hat A)\cdot\operatorname{sign}(a-\mu_{old})\cdot 0.15$ —
เข้าหา $a$ ถ้า action ดี หนีจาก $a$ ถ้า action แย่ (ตารางสี่กรณีใต้สมการ (G)) · ทั้ง e0 t2 และ e1 t1
มี $a > \mu_{old}$ ตัวคูณ $\operatorname{sign}(a-\mu_{old})$ จึงเป็น $+1$ ทั้งคู่ และ "ถูกทาง" ของ e0 t2 คือ
$+0.15$ ส่วนของ e1 t1 คือ $-0.15$ · แล้วลองกลับทิศดูด้วยว่าถ้า "เดินผิดทาง" ไกลเท่ากัน clip จะทำอะไร

| ช่อง | $\hat A$ | ขยับ | $\mu_{new}$ | $\rho$ | ในช่วง? | $-\rho\hat A$ | $-\text{clip}(\rho)\hat A$ | $L = \max$ | $\partial L/\partial\mu$ |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| e0 t2 | +0.9766 | ถูกทาง +0.15 | 0.25 | **1.2153** | ✗ > 1.2 | −1.1869 | **−1.1719** | **−1.1719 (คงที่)** | **0** |
| e1 t1 | −0.9290 | ถูกทาง −0.15 | −0.15 | **0.7520** | ✗ < 0.8 | +0.6986 | **+0.7432** | **+0.7432 (คงที่)** | **0** |
| e0 t2 | +0.9766 | ผิดทาง −0.15 | −0.05 | 0.7520 | ✗ < 0.8 | **−0.7344** | −0.7813 | −0.7344 | **−1.6157** ไหล |
| e1 t1 | −0.9290 | ผิดทาง +0.15 | 0.15 | 1.2153 | ✗ > 1.2 | **+1.1291** | +1.1148 | +1.1291 | **+1.1291** ไหล |

**อ่านสองแถวบน:** พอ $\rho$ หลุดกรอบ $[0.8, 1.2]$ ใน **ทิศที่ถูก** $\max$ เลือกพจน์ที่ถูก clip
ซึ่งเป็น**ค่าคงที่** → อนุพันธ์ = 0 → **หยุดผลัก** · ระบบพูดว่า "เข้าหา/หนี action นี้มา 20% แล้ว
พอ รอข้อมูลใหม่"

**อ่านสองแถวล่าง:** $\rho$ หลุดกรอบเท่ากันเป๊ะ แต่ใน **ทิศที่ผิด** — $\max$ กลับเลือกพจน์ดิบ
gradient ไหลเต็ม และเครื่องหมายของมันดึง $\mu$ กลับ · clip **ไม่เคยขวางการแก้ผิด**

> **ปลายการเทรน $\sigma$ เล็กลง clip จะทำงานถี่ขึ้นมาก** — จาก (7′) สองครั้งได้
> $\rho = \exp\!\Big(\tfrac{(a-\mu_{old})^2 - (a-\mu_{new})^2}{2\sigma^2}\Big)$ · ถ้า $\sigma = 0.25$ การขยับ +0.15
> เดียวกันบน e0 t2 ($a - \mu_{old} = 0.40$, $a - \mu_{new} = 0.25$) ให้
> $\rho = \exp\!\big(\tfrac{0.40^2 - 0.25^2}{2\cdot 0.25^2}\big) = \exp(0.78) = 2.18$ ทะลุกรอบไปไกล · นี่คือความหมายเชิงปฏิบัติของ trade-off ในโน้ต 05 หัวข้อ 4.6 เรื่องจำนวน epoch

**ตารางสรุปว่า clip ทำงานเมื่อไหร่** (ตรงกับที่โน้ต 05 หัวข้อ 4.5 อธิบายด้วยคำพูด):

| $\hat A$ | $\rho > 1+\epsilon$ (ชอบมากขึ้น) | $\rho < 1-\epsilon$ (ชอบน้อยลง) |
| --- | --- | --- |
| **+** (action ดี) | **clip · gradient 0** — "ดีพอแล้ว หยุด" | ไม่ clip · gradient ดึงกลับ — "ทำไมหนี action ดี" |
| **−** (action แย่) | ไม่ clip · gradient ผลักออก — "ทำไมชอบ action แย่" | **clip · gradient 0** — "หนีพอแล้ว หยุด" |

clip ปิด gradient เฉพาะ**ทิศที่เคลื่อนไปถูกทางแล้วและไกลพอ** — ไม่เคยขวางการแก้ผิด

### 5.4 Value loss — สอน critic

เป้าคือ $R$ จาก §4.4 · critic คายค่าใหม่ $V_{new}$ (weight $\phi$ เปลี่ยนไปแล้ว):

$$L_V = \text{mean}\Big[\max\big((V_{new} - R)^2,\; (V_{clip} - R)^2\big)\Big],
\quad V_{clip} = V_{old} + \text{clip}(V_{new} - V_{old}, -0.2, 0.2)$$

ตัวอย่างช่อง e0 t0 ($V_{old} = 5.0$, $R = 4.7278$):

| $V_{new}$ | $(V_{new}-R)^2$ | $V_{clip}$ | $(V_{clip}-R)^2$ | $L_V$ ช่องนี้ = max |
| --- | --- | --- | --- | --- |
| 4.9 | 0.0297 | 5.0 + clip(−0.1) = 4.9 | 0.0297 | 0.0297 |
| 4.5 | 0.0519 | 5.0 + clip(−0.5) = **4.8** | 0.0052 | **0.0519** (เลือกตัวใหญ่) |

$\max$ ทำให้ critic ถูก "ลงโทษแบบระวัง": ถ้ากระโดดไกล (−0.5) ก็ยังโดนคิดตามที่กระโดด
จริง ไม่ได้ผ่อนลง · gradient $\partial L_V/\partial V = 2(V - R)$ → ดัน $V$ เข้าหา $R$

### 5.5 Entropy — derive สำหรับ Gaussian

นิยาม $H = -\mathbb{E}[\log p(a)]$ · แทน (7') แล้วใช้ $\mathbb{E}[(a-\mu)^2] = \sigma^2$:

$$H = -\mathbb{E}\Big[-\tfrac12\ln 2\pi - \ln\sigma - \tfrac{(a-\mu)^2}{2\sigma^2}\Big]
= \tfrac12\ln 2\pi + \ln\sigma + \frac{\sigma^2}{2\sigma^2}
= \boxed{\tfrac12 + \tfrac12\ln 2\pi + \ln\sigma}$$

ที่ $\sigma = 0.5$: $H = 0.5 + 0.9189 - 0.6931 = \mathbf{0.7258}$ · ขึ้นกับ $\sigma$
อย่างเดียว — ยิ่ง $\sigma$ เล็ก $H$ ยิ่งต่ำ (ติดลบได้) · โบนัส $+0.01H$ ใน loss จึงต้าน
การหด $\sigma$ (โน้ต 05 หัวข้อ 4.5 ค)

### 5.6 รวม loss แล้วก้าว

$$L = L^{CLIP} + 1.0\,L_V - 0.01\,H$$

`loss.backward()` → gradient ทุก weight ($\theta$ ของ actor, $\phi$ ของ critic,
logstd) · `clip_grad_norm_(1.0)` · `optimizer.step()` → **จบ 1 gradient step** ·
ทำอีก 3 ครั้ง (mb₁, แล้ว epoch 2) = จบช่วง C

### 5.7 KL → ปรับ lr — derive สำหรับ Gaussian

KL ระหว่าง $\mathcal N(\mu_o, \sigma_o)$ กับ $\mathcal N(\mu_n, \sigma_n)$ (สูตรมาตรฐาน,
ตรงกับ [ppo.py:222-230](../tron1-rl-isaaclab/rsl_rl/rsl_rl/algorithm/ppo.py#L222-L230) ทุกพจน์):

$$KL = \ln\frac{\sigma_n}{\sigma_o} + \frac{\sigma_o^2 + (\mu_o - \mu_n)^2}{2\sigma_n^2} - \tfrac12$$

กรณี $\sigma$ เท่ากัน สองพจน์ตัดกันเหลือ $\dfrac{(\Delta\mu)^2}{2\sigma^2}$ · ที่ $\Delta\mu = 0.05$:
$KL = 0.0025/0.5 = \mathbf{0.0050}$

เทียบ `desired_kl = 0.01`: $0.005 < 0.02$ (ไม่ต้องลด lr) และ $0.005 = 0.005$ (พอดีขอบ
ล่าง ไม่เพิ่ม) → lr คงเดิม · แต่ถ้าใช้กฎ $\pm 0.15$ ของ §5.3: $KL = 0.0225/0.5 = \mathbf{0.045} > 0.02$
→ **lr ÷ 1.5** — ในช่องนี้ ก้าวที่ใหญ่พอให้ clip ทำงาน ก็ใหญ่พอให้เบรกอัตโนมัติทำงานด้วย ·
แต่**ไม่เสมอไป**: clip ดูรายช่องและขึ้นกับ $|a-\mu|$ ส่วน KL ดูค่าเฉลี่ยทั้ง batch และขึ้นกับ
$\Delta\mu/\sigma$ อย่างเดียว — action ที่สุ่มได้ไกลกว่า $\approx 1\sigma$ จะโดน clip ก่อนที่ KL จะแตะ 0.02

## 7. ทุกสูตรในหน้าเดียว — สำหรับเขียนบนกระดาน

เรียงตามลำดับที่เกิดจริง พร้อมระดับที่มันอยู่:

| # | ระดับ | สูตร | อ่านว่า |
| --- | --- | --- | --- |
| 1 | step | $a = \mu_\theta(s) + \sigma\varepsilon,\ \varepsilon\sim\mathcal N(0,1)$ | สุ่มรอบค่าที่ actor คิดว่าดี |
| 2 | step | $\log\pi = -\tfrac12\ln2\pi - \ln\sigma - \frac{(a-\mu)^2}{2\sigma^2}$ | เก็บไว้เป็นค่าอ้างอิง |
| 3 | step | $V = V_\phi(s)$ · $r, \text{done} = \text{env}(a)$ | critic เดา · โลกตอบ |
| 4 | iteration | $V_{last} = V_\phi(s_T)$ | bootstrap ที่ขอบตาราง |
| 5 | iteration | $\delta_t = r_t + (1-d_t)\gamma V_{t+1} - V_t$ | critic พลาดเท่าไหร่ |
| 6 | iteration | $A_t = \delta_t + (1-d_t)\gamma\lambda A_{t+1}$ | เครดิตสะสม ย้อนหลัง |
| 7 | iteration | $R_t = A_t + V_t$ | เป้าของ critic |
| 8 | iteration | $\hat A = (A - \bar A)/\text{std}_{n-1}(A)$ | เทียบกับเพื่อนในตาราง |
| 9 | minibatch | $\rho = \exp(\log\pi_{new} - \log\pi_{old})$ | ชอบมากขึ้นกี่เท่า |
| 10 | minibatch | $L^{CLIP} = \text{mean}\max(-\rho\hat A, -\text{clip}(\rho)\hat A)$ | ให้รางวัลแต่ไม่เกิน 20% |
| 11 | minibatch | $L_V = \text{mean}\max((V-R)^2, (V_{clip}-R)^2)$ | สอน critic |
| 12 | minibatch | $H = \tfrac12 + \tfrac12\ln2\pi + \ln\sigma$ | ยังสำรวจอยู่ไหม |
| 13 | minibatch | $L = L^{CLIP} + L_V - 0.01H$ · $\theta \leftarrow \theta - \alpha\nabla_\theta L$ | ก้าวหนึ่งก้าว |
| 14 | minibatch | $\partial L/\partial\mu = -\hat A\rho(a-\mu)/\sigma^2$ | **ทิศทางการเรียนรู้** |
| 15 | minibatch | $KL = \ln\frac{\sigma_n}{\sigma_o} + \frac{\sigma_o^2+(\Delta\mu)^2}{2\sigma_n^2} - \tfrac12$ → lr ×/÷ 1.5 | เบรกอัตโนมัติ |
| — | episode | *(ไม่มี)* — แค่ $d_t$ ในสูตร 5–6 | reset + วัดผล |

**ถ้าต้องอธิบายให้คนอื่นใน 3 ประโยค:**
(1) ทุก step สุ่ม action รอบ $\mu$ แล้วจดว่า "ตอนนั้นชอบมันแค่ไหน" ($\log\pi_{old}$)
(2) ครบตารางแล้ว ให้เครดิตแต่ละ action ย้อนหลังด้วย GAE เทียบกับที่ critic คาด
(3) แล้วขยับ $\mu$ เข้าหา action ที่เครดิตบวก หนีจากที่เครดิตลบ — แต่ไม่เกิน 20% ต่อรอบ
ทำซ้ำ 20 ครั้งต่อตาราง 15,000 ตาราง
